## 范围

依据 [容器化部署规划](../tech/容器化部署.md)，未来将现有前后端打包为一个应用镜像，与 PostgreSQL 在单机运行。选型理由见 [ADR-004](../adr/ADR-004-单机容器化部署.md)。本任务只允许部署必要的代码适配，不新增 npm/pip 包、静态服务器、代理或其他服务组件。

## 执行顺序与产出

| 阶段 | 前置条件 | 未来产出 | 验收出口 |
|---|---|---|---|
| D0 · 环境与基线 | 获得实施授权 | 主机架构、访问模式、既有 TLS 条件、镜像与备份位置；重新核对届时 master | 环境清单齐全，不靠新增组件补齐缺项 |

| D2 · 容器打包 | D1 | 单应用多阶段 Dockerfile、严格构建上下文、Compose、无密钥配置示例 | app + db 两常驻服务可用，迁移失败阻止启动，无 Node 运行层 |
| D3 · 数据与运维 | D2 | 内容包契约、显式导入、发布清单、备份/恢复/回退 SOP | 重复导入不重复；重建不丢数据；隔离恢复成功 |
| D4 · 容器验收 | D3 | 复用现有 pytest/Playwright 验证 PostgreSQL 与生产入口 | A1–A12 有证据，未通过项阻止发布 |
| D5 · 正式部署（未来执行） | D4；访问和证书条件齐备 | 指定主机上的已验证版本、备份与运行记录 | 用户隔离、HTTPS（非回环访问）、恢复路径可用 |

上述阶段不授权本轮实施。未来每个独立 feature 使用从 master 创建的独立 worktree，通过 PR 合并。

## 拟涉及文件

以下是未来候选清单，当前没有创建这些实现文件或改动这些代码。

| 文件/目录 | 用途 |
|---|---|
| 根目录 `Dockerfile`、`.dockerignore` | Node 构建前端 + Python 运行现有应用；显式 COPY 和构建白名单 |
| `deploy/compose.yaml`、`deploy/.env.example` | app/db、迁移/导入作业、端口/卷/非敏感变量；不含新网关服务 |
| `backend/app/main.py` 或独立静态路由模块 | 复用 FastAPI 的静态响应，适配现有前端页面路由，正确保留 API 错误 |
| `backend/app/config.py`、`backend/alembic/env.py` | 生产配置校验、标准库读取 secrets、URL 转义 |
| `backend/app/seed.py` 或独立导入模块 | 公共导入与私有配置迁移分离；不创建默认账号、不自动建表 |
| `tools/dump-data.js` | 增补版本和校验信息；保留现有公共数据边界，过滤不可共享路线 |
| 依赖锁定文件和已有测试配置 | 固定当前依赖的可复现集合，复用 pytest/Playwright，不增加包或测试框架 |
| 运维文档及必要的标准库/现有工具脚本 | 发布、备份、证书替换与恢复；不引入额外守护服务 |
