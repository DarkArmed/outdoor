# ADR-006-攻略语料采集方式

> ADR-006 · v1.0 · 2026-10-05 · 已确认

关联需求：PRD-006（攻略语料采集）。

## 背景

需要从小红书、微博、携程等内容平台采集户外攻略原文，搭建本地语料库。2026-10-05 对候选数据源做了实测（过程与数据见 `docs/tech/攻略流水线.md` 第一节），各源反爬强度差异大，采集方式需要取舍。同日用户确认了优先级、视频阈值与目的地限额，本文件由草稿转为已确认。

## 决策

1. **采集通道统一用真实浏览器自动化（Playwright），不逆向平台接口签名。**
   - 小红书搜索接口需要 `x-s`/`x-t` JS 签名，逆向成本高、随版本失效快，且有账号封禁风险；浏览器自动化模拟真实用户行为，维护成本低。
2. **源优先级：小红书 P0（最高）、微博 P1、携程 P1、马蜂窝 P2（2026-10-05 用户确认）。**
   - 小红书内容最匹配「新手亲子」场景，用户指定为最高优先级；当日已扫码登录验证搜索可用，采集限速执行最保守档位，尽量规避风控；
   - 微博移动版实测免登录可读全文与视频，户外亲子博主活跃，作为免登录主力补充；
   - 携程游记免登录且自带结构化元数据（天数/花费/出行人），但已公告 2025-11-30 停运，按「存量一次采完」处理，不建周期任务；
   - 马蜂窝搜索被归并到目的地页、内容偏长途，仅作补充。
3. **一期只存原文（raw），不定标准化格式。**
   - 语料形态未经验证（图文比例、攻略结构化程度），先积累再定 schema，避免标准化格式反复推翻。raw 格式（meta.json + text.md + 媒体目录）保证二期无需重采即可处理存量。
4. **视频设 20MB 下载阈值（用户确认），超限只存封面与直链。**
   - 控制语料库体积膨胀；阈值可配置。
5. **同一目的地采集不超过 5 篇（用户确认），范围暂限北京周边。**
   - 目的地按关键词分组计数，防止单一热门地点挤占语料库；北京周边以外目的地本期不采。
6. **遇反爬升级即停采该源，不对抗（不破解滑块、不接打码平台）。**
   - 个人家庭项目，账号与时间成本都不值得投入对抗；源失效就降级或放弃。

## 备选方案（已否决）

- **裸 HTTP + 接口逆向**：过不掉微博 visitor 系统、携程 whaleguard、小红书签名三者中的任何一个，否决。
- **第三方采集服务/数据商**：付费且数据新鲜度不可控，个人项目体量不需要，否决。
- **一期直接定标准化 schema 入库**：语料形态未知，schema 无依据，推迟到二期。

## 影响

- 引入 Python + Playwright 工具链（`tools/guide-pipeline/`），与 Node 的路线流水线并存、互不依赖。
- `corpus/` 与登录 cookie 不进 git；语料仅供个人规划参考，保留出处，不二次分发。
