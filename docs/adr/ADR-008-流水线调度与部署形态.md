# ADR-008-流水线调度与部署形态

> ADR-008 · v0.9 · 2026-10-15 · 草稿

关联需求：PRD-008（数据流水线与后台管理）；关联调研：INV-001（小红书采集窗口规律）。

## 背景

攻略语料采集要从「手动跑批次脚本」升级为常驻、动态调度的生产级流水线（PRD-008）。需要决策：worker 部署形态、调度器方案、容器内浏览器来源、阶段扩展架构、预算账本归属、管理员权限模型。

部署上遇到一个既有约束：ADR-005 决定「仅保留两个常驻服务（应用 + PostgreSQL），不引入新组件」。2026-10-15 用户在方案评审中确认选择「compose 新增 worker 服务」形态，本 ADR 据此对该条做正式复议修订。

## 决策

1. **compose 新增 `pipeline` worker 常驻服务——修订 ADR-005「仅两个常驻服务」为「三个」。**
   - 采集执行依赖真实浏览器（ADR-006）与本机语料库/登录 cookie，与 Web 应用生命周期完全不同：采集重（浏览器进程）、Web 轻（API 响应）。同进程会互相拖累，独立服务可单独重启、单独扩缩资源。
   - 其余约束不变：仍不引入 Redis、消息队列、K8s 等组件；worker 与 app 共用同一个 PostgreSQL。
2. **调度器自研：DB 轮询（约 30s tick）+ 作业表 `next_run_at`，不引入 APScheduler/Celery。**
   - INV-001 的核心调度语义是**自适应**的：streak 后冷却 ×2 封顶 48h、按运行结局计算下次运行时间——这不是 cron 语义，用 APScheduler 也得编程式动态重排，框架价值有限；
   - 作业量级极小（每天几轮），轮询开销可忽略；作业定义落 DB 天然支持「改参数不重启」（PRD-008 2.2.2）；
   - 零新增依赖，与 ADR-005「不引入新组件」精神一致。
3. **worker 用独立镜像（`Dockerfile.worker`，Playwright 官方基础镜像），app 镜像不变。**
   - app 镜像（python:slim）不含浏览器，把 Chromium 打进 app 镜像会无谓增大 Web 服务体积与攻击面；Playwright 官方镜像自带浏览器与系统依赖，版本与 Python 包锁死，省去手工装依赖的脆弱性。
4. **流水线按「阶段注册」架构组织：本期实现 collect，process/consume/emit 仅占位。**
   - 阶段接口统一（输入上下文 → 执行 → 结局 + 下次运行时间），新阶段/新源走注册表加入，不改调度器核心；
   - emit 阶段未来产出与 PRD-007 转换链同一交接点（备用方案、人工终审），不在本期实现。
5. **请求预算账本落 DB（事件级台账，24h 滑动窗口求和），替代批次脚本的进程内计量。**
   - 解决既有技术文档自陈的「无跨批次统一额度账本」缺口：任何作业/批次的请求统一入账，worker 单实例 + DB 约束替代 15 份分叉 collect.py 的各自为政；
   - 语料事件同时写本地 events.jsonl（向后兼容既有批次工具）与 DB（dashboard 数据源）。
6. **管理员权限用 `users.is_admin` 单列布尔 + 命令行开通，不建角色系统。**
   - 本期只有「管理员 / 非管理员」两种身份，RBAC 是过度设计；开通走服务端 CLI（`promote_admin`），不提供任何自助入口（PRD-008 2.5.1）。

## 备选方案（已否决）

- **调度器收进 app 进程（lifespan 后台任务）**：部署零变化，但采集（浏览器重负载）与 Web 同进程互相拖累，生产容器仍需解决浏览器与语料卷问题，否决（用户评审时未选）。
- **APScheduler / Celery / RQ**：自适应冷却语义不匹配 cron 模型，且引入新组件违背 ADR-005 精神，否决。
- **worker 跑在宿主机（不进容器）**：语料与 cookie 本就在宿主机，最省事；但环境依赖本机 Python/浏览器安装，不可复现，与项目容器化方向不一致，否决（用户评审时未选）。
- **admin 独立用户表 / 角色权限系统**：本期两种身份足够，过度设计，否决。

## 影响

- `deploy/compose.yaml` 增加第三个常驻服务；ADR-005 的「两个常驻服务」条文自本 ADR 起以「三个」为准（ADR-005 原文不改，追加式）。
- 语料库 `corpus/` 与 cookie 目录以 volume 挂入 worker 容器，仍为 gitignore 本地数据，合规红线（PRD-006 2.4）不变。
- 后端新增三张流水线表（作业 / 运行 / 事件）与 `users.is_admin` 列；字段契约见 `docs/tech/数据契约.md`。
- 批次脚本（`corpus/collection/*/collect.py`）不再演进，机制收编进 `tools/guide-pipeline/` 核心与 `app/pipeline/`；历史批次目录保留只读。
