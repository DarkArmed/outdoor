# ADR-005 · 单机容器化部署

> 编号：ADR-005 ｜ 版本：v1.1 ｜ 日期：2026-10-05 ｜ 状态：**已确认（本机范围）**
> 关联需求：[PRD-001](../prd/PRD-001-网站需求.md) 的服务化方向、[PRD-004](../prd/PRD-004-多用户与方案出行计划解耦.md) 的用户数据持久化。
> 关联技术：[容器化部署规划](../tech/容器化部署.md)。本机已按此选型实施；完整生产目标仍有待办，实际范围见 [容器化本机验证](../tech/容器化本机验证.md)。

## 背景与约束

以下背景记录初始规划时的代码状态。用户随后要求本机验证，现已新增容器配置及必要适配；仍遵守不引入新依赖的约束。容器化决策改编号为 ADR-005，避免与 master 已合入的小程序 ADR-004 冲突。

用户要求创建独立 worktree，只做容器化部署规划，并明确「不引入新依赖」。部署地点尚未确定，已选择按单台 Linux 主机、Docker Compose、小规模自用设计。

现状基线为 master `caa0fe7`：React/Vite 前端及用户流程已完成，FastAPI + SQLAlchemy + Alembic 后端已存在；公共内容迁至 `data/`，`site/` 已退役。当前没有容器构建与编排配置，FastAPI 也尚未托管前端构建产物。

## 决策

**仅保留两个常驻服务：应用容器与 PostgreSQL。应用镜像包含 React 构建产物和现有 Python 后端，由 FastAPI/Uvicorn 同时提供网页与 `/api`。** 迁移、公共内容导入复用同一应用镜像，作为显式的一次性作业执行。

| 决策 | 理由及影响 |
|---|---|
| 单机 Docker Compose | 满足当前小规模部署，接受维护窗口与主机单点故障；Docker/Compose 属于用户要求的容器运行环境。 |
| 复用 FastAPI 的 StaticFiles/FileResponse 与 Uvicorn | 不新增 npm/pip 包或 Web 服务器；现有 Starlette 能力由 FastAPI 提供，不新增单独依赖。需要少量静态路由适配。 |
| 单应用镜像、同源 `/api` | 前后端版本一起发布和回退，浏览器无须解析容器域名，也不需要新的反向代理。前后端源码仍分目录维护。 |
| Node 只出现在构建阶段 | 使用既有 Vite 工具链生成 dist，Python 运行层只带产物；目标主机无须额外安装 Node/Python。 |
| PostgreSQL 单独容器与命名卷 | 延续项目既定数据库选型，容器重建不改变业务数据生命周期。SQLite 保留现有测试用途。 |
| 独立迁移、显式导入 | 应用启动不改表或创建默认账号；迁移失败阻止发布。 |
| 复用已有 HTTPS 条件 | 若目标环境已有 TLS 入口则接入；否则 Uvicorn 使用运维提供的证书。证书签发/续期不增加新客户端或容器。条件不具备时先限本机验证。 |
| 固定镜像摘要和发布清单 | 记录代码、迁移、内容版本，支持检查和回退，不以 latest 作为回退依据。 |

FastAPI 可使用 StaticFiles 提供静态文件，底层来自它既有的 Starlette 依赖；SPA 深链接回退仍需项目代码明确处理。本规划不依赖较新版本才提供的 `app.frontend()`，也不要求升级现有 FastAPI。[官方说明](https://fastapi.tiangolo.com/tutorial/static-files/)。

## 未采用的方案

| 方案 | 原因 |
|---|---|
| Caddy、Nginx 或其他独立静态服务器 | 会增加项目没有的服务组件，不符合用户约束。 |
| Gunicorn、WhiteNoise、额外 Python/Node 服务框架 | 现有 FastAPI/Uvicorn 可以覆盖首期需求，无须新增依赖。 |
| Vite dev/preview 作为生产前端服务 | 增加常驻 Node 进程，不能替代生产静态托管设计。 |
| 应用与数据库放入同一容器 | 生命周期与持久化混合，恢复和升级边界不清楚。 |
| Kubernetes、Redis、消息队列 | 当前没有对应需求；不引入。 |

## 后果与复议条件

- 静态文件和 API 共用进程资源，不能独立扩容；首期接受，验收时测资源和响应，不承诺高吞吐或零停机。
- 不提供自动证书申请/续期能力。外部入口或已有证书的运维责任需明确，公网条件不齐时不发布。
- 已修正生产自动建表、固定 seed 账号、生产配置校验和就绪探针；这些适配已在本机实现，不增加依赖；公共内容通用导入仍待实现。
- 路线按方案共享，不能借部署自动获得逐用户路线隔离；不能导入家庭起点轨迹作为共享路线。
- 暂定最多丢失 24 小时数据、4 小时内恢复，须通过异机备份和恢复演练证明。
- 只有容量、可用性或访问需求变化，且用户允许新增依赖时，才另立决策重新评估网关等组件。
