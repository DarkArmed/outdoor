# ADR-007-语料转方案的提取方式

> ADR-007 · v1.0 · 2026-10-11 · 已确认（用户 2026-10-08 委托定稿；PoC 与实现验证均通过）

关联需求：PRD-007（语料转出行方案）。

## 背景

二期要把非结构化的攻略原文（小红书攻略、微博随笔、携程游记、官方介绍）转换为符合 PLANS 数据契约的结构化方案。提取方式有多种合理做法，需要取舍。

## 决策

**LLM agent 辅助提取 + 确定性工具校验 + 人工终审**：

1. **提取由 LLM agent 完成**：agent 读取工具产出的证据包（选料后的语料全文+元数据），起草方案草稿（draft JSON，事实块带语料溯源）。
   - 攻略是自由文本，时间线/门票/强度等信息散布在叙述中，LLM 是唯一现实的高质量提取手段；
   - agent 同时承担「原创重写」：综合多条语料的事实，用自己的话组织方案文字，满足合规红线（不抄原文、不署名）。
2. **工具只做确定性工作**：选料（别名+全文检索、排序）、契约校验、合规检查（n-gram 重合、作者名/平台名/链接）、幂等落盘。这些可测试、可重复，不依赖 LLM。
3. **人工终审后才可用**：新方案一律 `archived: true` 进备用计划区，不自动排期；用户看过才启用。
   - 户外方案涉及安全（强度、风险），全自动发布不可接受。

## 备选方案（已否决）

- **纯规则/模板提取**：攻略格式千差万别（实测小红书时间线符号、微博随笔、携程章节各不相同），规则覆盖率低成本高，提取质量不可控，否决。
- **全自动 LLM 流水线（无人工终审）**：安全风险（强度误判、风险漏提示）与合规风险（原文泄露）无法把关，否决。
- **全人工阅读撰写**：400+ 条语料人工读完再写，速度上不去，二期目标落空；保留人工终审环节即可，否决。

## 影响

- 新增 `tools/plan-pipeline/`（Python，无新第三方依赖），与 guide-pipeline 并存；
- 提取环节依赖 agent 会话，不能无人值守跑批量——一次一个目的地是预期节奏；
- 中间产物（证据包、draft JSON）含语料引用，存 `corpus/derived/`（gitignore），不进 git。
