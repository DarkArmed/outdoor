# 路线流水线（tools/route-pipeline/）机制

> 版本：v1.0 ｜ 日期：2026-08-07
> 把 PLANS 变成真实地理路线数据 ROUTES。三步：地理编码 → 路径规划 → 提取抽稀，产物写入 `site/js/data/routes.js`。
> 怎么跑、怎么申请 Key 见模块 `README.md`；本文档讲内部机制。

## 文件分工

| 文件 | 职责 |
|---|---|
| `pipeline.js` | 主流程：读 PLANS → 逐计划处理 → 合并写 routes.js；道路提取、地标、抽稀；`--network` 参数只刷路网 |
| `amap.js` | 高德 Web 服务 API 封装：限速、重试、缓存、编码兜底 |
| `gcj.js` | WGS-84 → GCJ-02 坐标转换（供路网用） |
| `overpass.js` | OSM Overpass 路网抓取 |
| `mock.js` | 无 Key 时生成白河湾示例数据（会覆盖 routes.js） |
| `config.json` | 本地配置（gitignore）：仅 `amapKey`。**家的位置/城市在 `config/profile.json`（用户配置）** |

## 地理编码兜底（amap.js geocode）

三级回退，任一级命中即返回：

1. 地理编码 API（带城市限定）
2. 地理编码 API（不限城市）
3. POI 搜索（place/text）

高德云图数据盲区（山野景点无编码结果）返回 30001——按**软失败**处理：返回 null、不抛错、**不写缓存**（避免缓存住失败结果）。外地同名 POI 张冠李戴用计划数据的 `drive.geoCity` 限定城市解决（如坝上限定承德）。

## 限速与缓存

- 高德个人开发者 QPS 低：每次调用前基础间隔 400ms；遇到限流错误码 10021 按 800ms 递增退避重试，最多 4 次。
- 所有调用结果写 `.cache.json`（gitignore），重跑增量快；只有软失败不缓存。

## 道路与地标提取（pipeline.js）

- `MAJOR_ROAD` 正则命中高速/环路/国道/省道/编号路（G\d+/S\d+）进 major 列表，其余进 minor；最终合并（major 优先，总数 ≤8）。
- 跳过出口/入口/收费站/匝道/辅路（`SKIP_ROAD`）。
- 每条道路用 `pointAtFraction` 在路径折线上取一个代表点，供地图放路牌。
- 地标按 `landmarkIcon` 规则配 emoji（湖/山/城区/寺庙等），逐个编码取真实坐标，距路线过远的丢弃（`distToPolyline`）。

## 抽稀

折线用 Ramer-Douglas-Peucker 抽稀后写产物，控制 routes.js 体积（容差是代码常量，可调）。

## 徒步路径

1. waypoint 有 `query` 的逐个编码；只有 `at` 的按比例插值在已有点连线上。
2. 相邻点间尝试高德步行路径规划：成功 → 真实轨迹，`pathSource: 'amap-walking'`；山野步道无覆盖 → 点位直线示意连接，`pathSource: 'schematic-link'`（页面注明示意）。

## 写入策略

`main()` 合并式覆盖：读已有 routes.js → 替换本次处理成功的 planId → 整体重写。**处理失败的计划保留旧数据**，不会因一次失败丢图。`node pipeline.js <planId>` 只处理指定计划；`archived: true` 的计划跳过。

## 路网抓取

- `overpass.js`：Overpass API 查 `[minLat,minLon,maxLat,maxLon]` 范围内 motorway/trunk/primary 三级道路几何，3 个镜像轮询（overpass-api.de / kumi.systems / nchc.org.tw），结果经 `gcj.js` 转 GCJ-02。
- **必须 POST + 自定义 User-Agent**：Overpass 对默认 UA 的客户端返回 406（2026-08 实测踩坑）。
- `pipeline.js buildNetwork()`：抓取 → 抽稀瘦身 → 写 `site/js/data/network.js`；**抓取失败保留已有文件**，不会清空。`node pipeline.js --network` 可单独刷新。
- 数据来源选型理由见 ADR-001。
