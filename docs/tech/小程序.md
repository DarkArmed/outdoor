# 小程序（miniprogram/）

> 版本：v1.1 ｜ 日期：2026-10-03

微信小程序客户端的技术机制：目录结构、配置、认证流程、API 用法、客户端约定。需求见 PRD-005，选型理由见 ADR-004。

## 一、技术栈与结构

原生微信小程序（WXML/WXSS/JS），无构建链、无 npm 依赖。ES2020 语法（开发者工具默认转译）。

```
miniprogram/
├── project.config.json   # 工程配置（appid 为占位符 touristappid）
├── app.js                # 入口：启动恢复登录态、globalData
├── app.json              # 页面注册、3 个 tab、窗口样式
├── app.wxss              # 全局样式：设计 token + 公共类
├── config.js             # API baseURL 等环境配置（唯一需要按环境改的文件）
├── assets/               # 本地 PNG：地图 marker 图标（pin-home/pin-dest/dot-blue/dot-green）、
│                         #   tabBar 图标（tab-*-normal/selected）；marker iconPath 必填，须随包上传
├── utils/
│   ├── api.js            # request 封装 + 全部后端端点函数
│   ├── auth.js           # 登录/静默重登/退出、token 存取
│   ├── badges.js         # 新增里程碑集合差、统计计算
│   └── plan.js           # 方案/出行内容工具：扁平索引、月份分组、类型色

│   ├── trips/            # Tab2 我的出行
```

## 二、配置

`config.js` 导出 `{ apiBaseUrl }`，开发默认 `http://localhost:8000`，发布前改为生产 https 域名。后端需在 `.env` 配置（`.env.example` 有模板）：

| 环境变量 | 说明 |
|---|---|
| `WECHAT_MINIAPP_APPID` | 小程序 AppID（空 = 未配置） |
| `WECHAT_MINIAPP_SECRET` | 小程序 Secret |

`DEBUG=true` 且 AppID 未配置时，后端走 mock code2session（确定性 `dev_` 前缀 openid），供本地开发；配置了真实 AppID 后该分支不生效。生产必须 `DEBUG=false` + 真实 AppID/Secret。

## 三、认证流程

1. `wx.login()` 得 code → `POST /api/auth/wechat/miniapp` `{code, nickname?}` → 得 `{access_token, token_type, is_new_user, user}`。
2. token 存 `wx.setStorageSync('token')`；之后所有请求带 `Authorization: Bearer <token>`。
3. 任一请求收到 401 → 清除 token → 静默重登一次（wx.login 无感）→ 重放原请求；重登失败 → 跳登录页。
4. 退出登录：清本地 token 与用户缓存，跳登录页（服务端 token 自然过期，无登出端点）。

### 新端点契约

`POST /api/auth/wechat/miniapp`（JSON，不需登录）：

```jsonc
// 请求
{ "code": "wx.login 的 code", "nickname": "可选" }
// 响应 200
{ "access_token": "...", "token_type": "bearer",
  "is_new_user": true, "user": { "id": 1, "email": "wx_oXxx@wechat.local",
  "nickname": "微信用户", "is_active": true, "created_at": "..." } }
```

错误：微信返回 errcode（如 40029/40163 code 无效或已用）→ `400 {"detail": ...}`；无法连通微信 → `502`；未配置 AppID 且非 debug → `503`。

服务端行为：按 `wechat_openid` 查用户，存在则直接签发；不存在则创建（email 占位 `wx_<openid>@wechat.local`、随机不可用密码散列、nickname 取入参或「微信用户」）。`UserOut` 新增 `nickname: str|null`。

## 四、API 用法（既有端点）

| 场景 | 端点 |
|---|---|
| 方案列表 | `GET /api/plans?archived=false` / `archived=true`（备用区） |
| 方案详情 | `GET /api/plans/{plan_id}` |
| 我的出行列表 | `GET /api/trips` |
| 创建出行 | `POST /api/trips` `{plan_id, planned_date?}` → 201 |
| 出行详情（合并后内容） | `GET /api/trips/{id}` → `content` 字段为 snapshot+overrides 合并结果 |
| 改日期/状态 | `PUT /api/trips/{id}` `{planned_date?}` |
| 删除出行 | `DELETE /api/trips/{id}` → 204 |
| 出行路线 | `GET /api/trips/{id}/route` → `drive`/`hike`（GCJ-02） |
| 装备状态 | `GET/PUT /api/trips/{id}/gear`，PUT body `{items:[{item_idx, checked}]}` |
| 任务状态 | `GET/PUT /api/trips/{id}/tasks`，同上 `task_idx` |
| 打卡 | `POST /api/trips/{id}/checkin` → 201（幂等，同时置 status=done 并由后端颁发活动徽章与里程碑） |
| 里程碑规则 | `GET /api/milestones` → `[{id, icon, name, rule}]` |
| 我的徽章 | `GET /api/me/badges` |
| 画像 | `GET /api/profile`（404 = 未设置） |

## 五、客户端约定

- **gear/task 扁平索引**：`gear` 是 `{base: [...], special: [...]}` 字典，`item_idx` 为按对象键插入序（base 在前 special 在后）展开后的全局下标，与网站 localStorage 约定（`gear:<planId>:<idx>`）一致。任务 `task_idx` 为 `tasks` 数组下标。
- **勾选写策略**：乐观更新 UI → `PUT …/gear` `{items:[{item_idx, checked}]}`（单项数组）→ 失败回滚该项并 toast。
- **月份分组**：方案 `id` 形如 `2026-09-05`，取前 7 位（`YYYY-MM`）分组；不匹配该格式的归入「其他」。
- **地图渲染**：`GET …/route` 的坐标一律为 `[lng, lat]` 数对（GCJ-02）：`drive.polyline`/`hike.path`（可能为 null）是数对数组，`drive.from/to`、`drive.landmarks[]`、`hike.spots[]` 为 `{name, icon?, act?, coord:[lng,lat]}`；另有 `drive.distance`(km)/`drive.duration`(分钟)。客户端转换为 `<map>` 格式（`{latitude: c[1], longitude: c[0]}`）：polyline 画驾车线与徒步路径；from/to、landmarks 转 markers；徒步 spots 按顺序显示序号标记。无 route（404）或 `hike.path` 为 null 时对应区块显示占位提示。
- **打卡与徽章**：长按 2 秒（touchstart 计时 + touchend/cancel 取消，CSS 进度动画）→ 读取打卡前的 `GET /api/me/badges` → `POST checkin` → 读取打卡后的徽章集合及里程碑定义。活动徽章以 `plan_id` 为 ID，里程碑以 `milestone.id` 为 ID，由后端在打卡事务中统一颁发；客户端不调用解锁接口，也不自行评估授奖条件。庆祝弹窗用打卡前后徽章 ID 的集合差展示新增里程碑，已解锁里程碑不重复提示。
  - 所有出行均可打卡，不以 `content.badge` 是否存在为条件；无活动徽章时弹窗展示 ✅ 完成确认，仍显示本次新增里程碑。
  - 打卡请求进行中及出行已完成时忽略重复触发；打卡失败保持原状态，允许重试。
  - 徽章读取失败不阻止打卡；打卡成功后立即保留已完成状态，若无法计算完整集合差则提示到「我的」查看徽章，不把刷新失败显示为打卡失败，也不将已有里程碑误报为新增。
- **满星版**：打卡时 `tasks` 全部勾选 = 满星，庆祝弹窗用金色样式（仅展示差异，无额外数据）。
- **统计（我的页）**：已冒险次数 = status=done 的出行数；徒步 km = 已完成出行 `content.hike.length` 首个数字之和（如「约 2km」→ 2）；露营晚数 = 已完成出行中 `content.theme ∈ {camp, campnight}` 的晚数之和（`day_names.length > 1` 时按 `length - 1`，否则按 1）。
- **年龄**：`profile.child.birthYear` 实时计算（当前年 − 出生年），不存储。

## 六、运行与调试

1. 先在 `backend/` 执行 `alembic upgrade head`，合流迁移同时兼容已运行的 Web 和微信登录数据库；再启动后端：`cd backend && uvicorn app.main:app --reload`（`.env` 按需配置）。
2. 微信开发者工具导入 `miniprogram/` 目录；无 AppID 时用测试号。
3. 开发期在「详情 → 本地设置」勾选「不校验合法域名」。
4. 无 AppID/Secret 时后端开 `DEBUG=true` 走 mock 登录。
5. 原型：`miniprogram/design/prototype/index.html` 浏览器打开查看全部页面设计稿。
6. 客户端回归测试：仓库根运行 `node --test miniprogram/tests/*.test.js`，使用 Node 内置测试器与微信页面替身，无 npm 依赖；覆盖后端颁奖后的弹窗、重复触发、打卡/刷新失败及统计口径。
