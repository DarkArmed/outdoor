# 数据契约

> 版本：v1.1（草案） ｜ 日期：2026-09-13
> 项目数据源的字段定义 + localStorage 键 + 后端数据库实体契约。**这是网站、流水线、配置、后端数据库之间的交界面**，加减字段先改本文档再动代码。
> ⚠️ 全部使用占位示例，真实值只存在于 gitignore 的配置文件或运行期数据库。

## 一、PROFILE（用户配置）

- **源**：`config/profile.json`（gitignore，唯一真实来源）
- **模板**：`config/profile.example.json`（入库，占位值）
- **网站用派生物**：`site/js/data/profile.js`（`var PROFILE = {...}`，同步脚本生成，gitignore）

| 字段 | 类型 | 含义 | 消费方 |
|---|---|---|---|
| `home.name` | 字符串 | 家的大致位置（街道/地铁站级，不写门牌） | 流水线：自驾起点编码；计划数据 `drive.from`；路线图起点 |
| `home.city` | 字符串 | 所在城市 | 流水线：地理编码默认城市限定 |
| `family.travelers` | 字符串数组 | 常规出行成员 | 页面文案；装备/餐饮按人数 |
| `child.name` | 字符串 | 孩子小名 | 页面文案（头图、鼓励语等） |
| `child.birthYear` | 数字 | 孩子出生年份 | 年龄 = 当前年份 − birthYear，**展示时计算，不存年龄数字** |
| `child.enduranceKm` | `[下限, 上限]` | 孩子可接受的徒步里程范围 | 新计划强度匹配 |
| `child.interests` | 字符串数组 | 孩子兴趣 | 新计划选题 |
| `child.character` | 字符串 | 性格特点（自由文本） | 新计划节奏与安全提示 |
| `child.allergies` | 字符串数组 | 过敏/忌口（无则空数组） | 餐饮与药品清单 |
| `prefs.maxDriveHoursOneWay` | 数字 | 单程车程上限（小时） | 新计划目的地筛选 |
| `prefs.availableDays` | 字符串数组 | 可出行日 | 新计划排期 |
| `prefs.activityTypes` | 字符串数组 | 活动类型偏好 | 新计划选题 |
| `prefs.foodNotes` | 字符串 | 餐饮备注（无则空串） | 餐饮清单 |

## 二、PLANS（户外计划）

- **位置**：`site/js/data/data-a|b|c|d.js`，`var PLANS = []; PLANS.push({...})`，页面按 `id` 排序。
- 一条计划的完整字段：

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `id` | 字符串 `'YYYY-MM-DD'` | ✅ | 唯一键，出发日期；详情页 `?id=` 参数。备用计划允许非日期 id（如 `'stargaze-tanghekou'`），不参与月份归档排序 |
| `title` | 字符串 | ✅ | 计划名 |
| `date` | 字符串 | ✅ | 展示用日期（如 `'9/5（周六）'`） |
| `type` | 字符串 | ✅ | 周型（A 溯溪玩水 / B 山野徒步 / C 露营过夜 / D 骑行等），首字母决定徽标配色 |
| `theme` | 字符串 | ✅ | 插图主题，见 `scenes.js` 的 SCENES（water/hike/camp/campnight/cycle/grassland/lake/redleaf/climb/museum/snow/hero） |
| `emoji` | 字符串 | ✅ | 卡片/时间轴用表情 |
| `location` | 字符串 | ✅ | 展示用地点（如 `'怀柔·白河湾'`） |
| `archived` | 布尔 | 可选 | `true` 进首页备用计划区，流水线跳过 |
| `mom` | 布尔 | 可选 | `true` 妈妈同行：卡片/详情页显示「👩 妈妈同行」徽标，主题场景图加入妈妈角色（骑行主题为额外一辆自行车） |
| `badge` | 对象 `{icon, name}` | 活跃计划必填 | 活动徽章（PRD-002）：打卡后解锁，显示在首页徽章墙 |
| `tasks` | 字符串数组（3 条） | 活跃计划必填 | 小勇士任务（PRD-002）：观察自然类、零装备、可勾选 |

**里程碑徽章**：`var MILESTONES`（data-a.js），`{id, icon, name, rule}`；rule 三种写死：`{firstType:'C'}` 首个打卡的该周型 / `{count:N}` 累计打卡 N 次 / `{minKm:N}` 打卡计划的 drive.km ≥ N。显示状态按规则对 `plans:done` 实时评估。
| `drive.from` | 字符串 | ✅ | 起点名（用「家」指代，具体位置读 PROFILE） |
| `drive.to` | 字符串 | ✅ | 目的地名（可地理编码） |
| `drive.time` / `drive.km` | 字符串 / 数字 | ✅ | 展示用车程、里程 |
| `drive.landmarks` | 字符串数组 | 可选 | 沿途地标（城区/山水/建筑），可地理编码 |
| `drive.geoCity` | 字符串 | 可选 | 外地目的地的限定城市（防同名 POI，如坝上填 `'承德'`），作用于该计划全部编码请求 |
| `goal` | 字符串 | ✅ | 本周目标 |
| `tips` | 字符串数组 | 可选 | 「爸爸的小抄」 |
| `itinerary` | 数组 | ✅ | 单日：`[{time, text}, ...]`；多日：**数组的数组**，每天一段 |
| `dayNames` | 字符串数组 | 多日必填 | 每天的小标题，与多日 itinerary 一一对应 |
| `gear.base` / `gear.special` | 字符串数组 | ✅ | 基础装备 / 本周特殊装备（⭐ 表重点） |
| `safety` | 字符串数组 | ✅ | 安全要点 |
| `hike.title` / `hike.length` | 字符串 | ✅ | 徒步段标题 / 展示用长度 |
| `hike.waypoints` | 数组 | ✅ | 徒步关键点，见下表 |
| `review` | 字符串数组 | ✅ | 回顾问题 |

waypoint 字段（地理定位二选一或都给）：

| 字段 | 含义 |
|---|---|
| `name` | 点名（必填） |
| `query` | 可地理编码的锚点地名（如 `'青石岭村'`），流水线编码取坐标 |
| `at` | 沿徒步路径的比例 0–1（无 query 时按比例插值在路径上） |
| `icon` / `act` | 可选：图标 emoji / 活动事项标注（如 `'踩水·打水仗'`） |

## 三、ROUTES（路线数据，流水线产物）

- **位置**：`site/js/data/routes.js`，`var ROUTES = { "<planId>": {...} }`，**由流水线生成，勿手改**。
- 坐标系：GCJ-02（火星坐标），全程自洽。

| 字段 | 含义 |
|---|---|
| `source` | 数据来源（`'amap'` / `'mock'`） |
| `generatedAt` | 生成时间 ISO 串 |
| `drive.from` / `drive.to` | `{name, coord:[lon,lat]}` |
| `drive.polyline` | `[[lon,lat], ...]` 驾车路径（已抽稀） |
| `drive.roads` | `[{name, point:[lon,lat]}]` 沿路线提取的主要道路（≤8 条，point 为路上一点，用于放置路牌） |
| `drive.landmarks` | `[{name, icon, coord}]` 沿途地标真实坐标 |
| `drive.distance` / `drive.duration` | 公里 / 分钟（高德返回值） |
| `hike.spots` | `[{name, icon, act, coord}]` 徒步关键点真实坐标 |
| `hike.path` | `[[lon,lat], ...]` 徒步路径 |
| `hike.pathSource` | `'amap-walking'`（真实步行轨迹）/ `'schematic-link'`（API 无覆盖，点位直线示意连接，页面注明） |

## 四、NETWORK（路网背景）

- **位置**：`site/js/data/network.js`，`var NETWORK = {...}`，流水线从 OSM 抓取生成（决策见 ADR-001，机制见路线流水线.md）。
- 单独刷新：`node pipeline.js --network`；全量跑流水线时自动附带抓取，失败保留旧文件。

| 字段 | 含义 |
|---|---|
| `bbox` | `[minLat, minLon, maxLat, maxLon]` 抓取范围 |
| `ways` | `[{name, ref, cls, polyline}]` 主要道路折线，cls ∈ motorway/trunk/primary，坐标已转 GCJ-02 |

## 六、后端数据库实体（新增）

后端使用 PostgreSQL，ORM 为 SQLAlchemy 2.0。以下表/字段为后端 API 与数据库之间的契约。

### 6.1 `users`

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | UUID / 自增整数 | 用户唯一键 |
| `email` | 字符串（唯一） | 登录邮箱 |
| `hashed_password` | 字符串 | bcrypt 密码哈希 |
| `is_active` | 布尔 | 是否启用 |
| `created_at` | datetime | 创建时间 |

### 6.2 `profiles`

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | UUID / 自增整数 | 画像唯一键 |
| `user_id` | 外键 → users.id | 所属用户 |
| `home_name` | 字符串 | 家的大致位置 |
| `home_city` | 字符串 | 所在城市 |
| `family_travelers` | JSON | 常规出行成员列表 |
| `child` | JSON | `{name, birthYear, enduranceKm, interests, character, allergies}` |
| `prefs` | JSON | `{maxDriveHoursOneWay, availableDays, activityTypes, foodNotes}` |

### 6.3 `plans`（公共方案）

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | 字符串（保持原 plan id） | 公共方案唯一键 |
| `title` | 字符串 | 方案名 |
| `date` | 字符串 | 展示日期 |
| `type` / `theme` / `emoji` / `location` | 字符串 | 类型、主题、表情、地点 |
| `archived` / `mom` | 布尔 | 归档、妈妈同行 |
| `goal` / `tips` / `itinerary` / `day_names` | JSON | 目标、提示、行程、天名 |
| `drive` / `hike` / `gear` / `safety` / `review` | JSON | 自驾、徒步、装备、安全、回顾 |
| `badge` / `tasks` | JSON | 徽章、任务 |
| `created_at` / `updated_at` | datetime | 创建/更新时间 |

### 6.4 `trips`（用户出行计划）

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | UUID / 自增整数 | 出行计划唯一键 |
| `user_id` | 外键 → users.id | 所属用户 |
| `plan_id` | 外键 → plans.id | 引用的公共方案 |
| `snapshot` | JSON | 创建时从 plan 深拷贝的内容快照 |
| `overrides` | JSON | 用户覆盖项 |
| `status` | 枚举/字符串 | `planned` / `done` / `archived` |
| `planned_date` | 日期/字符串 | 用户安排的出行日期 |
| `created_at` / `updated_at` | datetime | 创建/更新时间 |

### 6.5 `routes`

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | UUID / 自增整数 | 路线唯一键 |
| `plan_id` | 字符串 | 对应公共方案 id |
| `source` | 字符串 | `'amap'` / `'mock'` |
| `generated_at` | datetime | 生成时间 |
| `drive` / `hike` | JSON | 与 §三 ROUTES 同结构 |

### 6.6 `networks`

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | UUID / 自增整数 | 路网唯一键 |
| `region` | 字符串 | 区域名 |
| `bbox` | JSON | `[minLat, minLon, maxLat, maxLon]` |
| `ways` | JSON | 与 §四 NETWORK 同结构 |

### 6.7 `milestones`

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | 字符串 | 里程碑唯一键 |
| `icon` / `name` | 字符串 | 图标、名称 |
| `rule` | JSON | `{firstType}` / `{count}` / `{minKm}` |

### 6.8 用户状态表

| 表 | 字段 | 含义 |
|---|---|---|
| `gear_states` | `trip_id`, `item_idx`, `checked`, `updated_at` | 装备勾选 |
| `task_states` | `trip_id`, `task_idx`, `checked`, `updated_at` | 任务勾选 |
| `checkins` | `trip_id`, `checked_in_at` | 打卡记录 |
| `badge_unlocks` | `user_id`, `badge_id`, `unlocked_at` | 徽章解锁 |

## 七、localStorage 键（本阶段保留）

第一阶段 `site/` 不动，localStorage 继续作为浏览器本机状态；后端已持久化同一份状态，供后续前端重写时迁移。

| 键 | 状态 | 含义 |
|---|---|---|
| `gear:<planId>:<idx>` | ✅ 已用 | 装备勾选，`'1'`/`'0'` |
| `badges:unlocked` | ✅ 已用 | 已解锁徽章 key 列表（JSON 数组） |
| `tasks:<planId>:<idx>` | ✅ 已用 | 任务卡勾选，`'1'`/`'0'` |
| `plans:done` | ✅ 已用 | 已打卡计划 id 列表（JSON 数组） |
