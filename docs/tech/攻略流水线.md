# 攻略流水线（guide-pipeline）

> v1.1 · 2026-10-08

从内容平台采集户外攻略**原文**（文字 + 图片 + 视频）到本地语料库的工具链。需求见 PRD-006；数据源选型理由见 ADR-006。本期只采集与存档，不做标准化。

## 一、数据源可行性（2026-10-05 实测）

| 源 | 裸 HTTP（curl） | 真实浏览器（未登录） | 结论（优先级为 2026-10-05 用户确认） |
|---|---|---|---|
| 微博移动版 `m.weibo.cn` | 被 Sina Visitor System 拦截（返回访客系统 JS 页） | ✅ 搜索页直接出结果：作者、时间、全文、视频时长/播放量 | **P1**。浏览器自动化免登录即可；visitor cookie 由浏览器自动解决 |
| 携程游记 `you.ctrip.com` | 432 `whaleguard block` | ✅ 列表页（含天数/出行人/玩法筛选）与详情页全文均可读 | **P1**。存量采集；游记业务 2025-11-30 停运，无增量 |
| 小红书 `www.xiaohongshu.com` | 200 但 `__INITIAL_STATE__.search.feeds` 为空，结果走 `/api/sns/web/v1/search/notes`（需 `x-s`/`x-t` 签名） | ❌ 搜索页登录墙，未登录零内容；**登录后（2026-10-05 扫码验证）搜索正常出结果**：笔记标题、作者、发布时间、点赞数、相关搜索词齐全 | **P0（最高）**。扫码登录拿 cookie + 浏览器自动化，不逆向签名；限速最保守 |
| 马蜂窝 `www.mafengwo.cn` | 202 + JS 挑战页 | ⚠️ 能过挑战，但关键词搜索被归并到目的地页，攻略列表不直接可见 | **P2**，只作补充 |

实测方法记录：curl 探测（各源首页/搜索页）+ 桌面浏览器验证渲染结果。探测产物未入库（第三方页面 HTML 不进 git）。

## 二、架构

```
tools/guide-pipeline/
├── pipeline.py          # 入口：python pipeline.py [--source weibo|ctrip|xhs] [--keyword "北京亲子徒步"]
├── config.json          # 关键词清单、视频阈值、限速参数、每源开关（gitignore 的 cookie 路径也在此配置）
├── sources/
│   ├── base.py          # SourceAdapter 抽象：search(keyword) -> [Ref]；fetch(ref) -> RawItem
│   ├── weibo.py         # m.weibo.cn 移动版（浏览器上下文 + 页面内 API）
│   ├── ctrip.py         # you.ctrip.com 游记列表/详情（浏览器渲染 + DOM 提取）
│   └── xhs.py           # 小红书（需登录 cookie，见第四节）
├── store.py             # 落盘：目录组织、索引、去重
└── media.py             # 媒体下载：图片原图、视频阈值判断、封面回退
```

技术选型：**Python + Playwright**（有头/无头浏览器）。理由：后端已是 Python 技术栈（`backend/requirements.txt`），依赖管理一致；三个 P0/P1 源都需要真实浏览器环境过反爬，Playwright 一套上下文通吃；不引入第三方爬虫框架。

与 `tools/route-pipeline/`（Node）的关系：相互独立、互不依赖；攻略流水线产出语料，路线流水线产出路线几何，二期标准化时才会交汇。

## 三、存储格式（raw，一期定稿）

语料根目录 `corpus/`（**gitignore**，媒文件不进库）：

```
corpus/
├── index.jsonl                    # 全局索引，一行一条：{source, id, title, keyword, destinations, url, fetched_at, n_images, n_videos, has_fulltext}
└── raw/
    └── <source>/                  # weibo / ctrip / xhs / mafengwo
        └── <source_id>/           # 平台原生 ID（微博 mblogid、携程游记 ID、小红书 note id）
            ├── meta.json          # 元数据（见下）
            ├── text.md            # 正文原文（保留换行；表情/话题标记原样保留）
            ├── images/001.jpg …   # 原图，按原文顺序编号
            └── videos/001.mp4 …   # ≤ 阈值的视频；超阈值则不建此文件
```

`meta.json` 字段契约：

| 字段 | 说明 |
|---|---|
| `source` / `id` | 源标识与平台原生 ID（联合主键，去重依据） |
| `url` | 原文链接（出处，必填） |
| `title` | 标题（微博无标题则取正文前 30 字） |
| `author.name` / `author.id` | 作者昵称与平台 ID（出处，必填） |
| `published_at` | 原文发布时间（ISO，源页面原始时区） |
| `fetched_at` | 采集时间（ISO） |
| `keyword` | 命中它的检索关键词（多关键词命中时追加为数组） |
| `destinations` | 命中的目的地/主题组（数组，见下「目的地限额」） |
| `stats` | `{likes, collects, comments, plays}`，缺项为 null |
| `media.images[]` | `{file, origin_url, width, height}` |
| `media.videos[]` | `{file|null, origin_url, cover, duration_s, size_bytes, skipped_reason}` |
| `raw_extra` | 源特有的剩余字段原样塞入（携程的天数/花费/出行人等），不做标准化 |

**视频阈值**：`config.json` 的 `video_max_bytes`，默认 **20MB**（20_971_520 字节，2026-10-05 用户确认）。超限视频记 `skipped_reason: "too_large"`，只存封面与直链；无法获取真实大小的先下响应头 `Content-Length`，头缺失则流式下载到阈值即中断并标记 `size_unknown_aborted`。

**目的地限额**：`config.json` 里按「目的地/主题组」组织关键词，每组 `cap` 默认 **5 篇**（2026-10-05 用户确认）。限额按**「组 × 源」分别计数**（2026-10-06 用户确认）：跨源合并计数会让先跑的源占满名额、P0 小红书永远轮不到。某源在某组已采篇数（按索引中 `destinations` + `source` 计数）达到上限后，该组关键词本轮跳过；一条语料命中多个组时各组分别计数。配置示例：

```json
{
  "video_max_bytes": 20971520,
  "destination_groups": [
    {"name": "泛主题-亲子徒步", "keywords": ["北京亲子徒步", "北京遛娃爬山"], "cap": 5},
    {"name": "白河湾", "keywords": ["白河湾"], "cap": 5},
    {"name": "神堂峪", "keywords": ["神堂峪"], "cap": 5}
  ]
}
```

**去重**：`index.jsonl` 按 `source + id` 查重。已存在的条目默认跳过媒体下载；加 `--refresh` 只更新 `meta.json` 的 `stats` 与 `fetched_at`。

## 四、各源采集策略

**微博（weibo.py）**：Playwright 打开 `m.weibo.cn/search?containerid=100103type=1&q=<关键词>`，滚动加载更多；从页面内 `render_data` / XHR 响应提取 mblog 列表；进详情页取全文（长文需点「展开」）、原图（`large` 尺寸）、视频（page/video 流地址）。免登录；出现风控页（验证码/登录强制）时退避 30 分钟并降速。

**携程（ctrip.py）**：列表页 `you.ctrip.com/travels/<目的地>/t3-p<n>.html` 分页（支持「和谁出行=亲子」「玩法=徒步/自驾」筛选维度，直接构造筛选 URL）；详情页 DOM 提取标题、结构化信息栏（出发时间/天数/人均/和谁出行 → `raw_extra`）、正文段落与图片。**正文模板有两种并存**（2026-10 实测）：旧版 `div.content` + `h5.menu`，新版 `div.travel-content-wrapper`，选择器需同时覆盖。作者/发布时间/互动数不在 DOM，只存在于页面内 Next.js flight JSON，用正则从原始 HTML 提取。whaleguard 拦裸 HTTP 但放行真实浏览器，一律走 Playwright；冷启动需先访问 www.ctrip.com 首页热身拿 cookie。注意 2025-11-30 停运公告：一次性把目标城市存量采完即可，不做周期任务。

**小红书（xhs.py）**：**P0 源，限速最保守**（搜索间隔 ≥ 8s、详情间隔 ≥ 5s，可配置）。首次运行 `--login` 打开有头浏览器扫码登录，cookie 存 `tools/guide-pipeline/.cookies/xhs.json`（gitignore）；之后复用。搜索页滚动采集笔记卡片 → 进详情取图文/视频（详情数据优先取页面内 `__INITIAL_STATE__.note.noteDetailMap`，DOM 兜底；视频提取：`n.video.media.stream` 是按流类型分组的对象（EF4/EF5/…），变体含 `masterUrl`/`size`/`duration`/`defaultStream`，时长在 `n.video.capa.duration`，封面取图集首图，2026-10-07 实测验证）。**关键细节（2026-10-05 实测）：搜索结果卡片有两种锚点——裸 `/explore/<id>`（无 `xsec_token`，直接打开必 404，error_code=300031）和 `/search_result/<id>?xsec_token=...`（真实可用），必须只收带 `xsec_token` 的链接。**触发滑块/验证即停采该源并提示人工处理，不自动对抗。2026-10-05 已扫码登录并完成试采验证（白河湾 2 篇：标题/正文/作者/赞藏评/原图齐全）。

**通用限速**：每源独立令牌桶，默认搜索请求间隔 ≥ 5s、详情页间隔 ≥ 3s、单源每日上限 200 条（均在 `config.json` 可调；小红书单独覆盖为更保守值）。媒体下载并发 ≤ 2，失败 3 次重试后记录 `skipped_reason`。

## 五、运行

```bash
cd tools/guide-pipeline
pip install -r requirements.txt   # playwright, 然后 playwright install chromium
python pipeline.py --source weibo --keyword "北京亲子徒步"
python pipeline.py --source ctrip --keyword "北京"   # 携程按目的地维度，keyword 即目的地
python pipeline.py --source xhs --login               # 首次：扫码登录
```

## 六、合规红线（代码层面强制执行）

- `meta.json` 缺 `url` 或 `author` 的条目拒绝落盘（出处必填）。
- User-Agent 用真实浏览器 UA，不伪造移动端 API 客户端。
- 语料目录 `corpus/`、cookie 目录 `.cookies/` 均在 `.gitignore`；提交前 `git status` 检查无媒体文件入库。

## 七、持续采集：进度入口与续采

采集是持续工作，批次目标只界定一轮任务。**文档维护记录位置、查询方法和续采规则；实时数量、失败清单和停止原因保留在本地数据中，不逐轮抄入文档。** 以下路径均相对保存语料的仓库根目录。

### 记录在哪里

| 路径 | 用途 | 更新方式 |
|---|---|---|
| `corpus/index.jsonl` | 全库已入库记录；按 `source + id` 去重，按 `destinations + source` 统计组限额 | 成功保存时由采集程序更新 |
| `corpus/raw/<source>/<id>/meta.json` | 单条出处、采集时间、媒体原始链接及缺失原因；正文和媒体在同目录 | 保存该条内容时更新 |
| `corpus/collection/<批次>/plan.json` | 批次目标、候选目的地、检索词与各源队列 | 准备批次时保存 |
| `corpus/collection/<批次>/events.jsonl` | 搜索、详情尝试、保存、失败、暂停和结束事件 | 批次运行时自动追加 |
| `corpus/collection/<批次>/index-before.jsonl` | 批次开始前的索引，用于计算新增量 | 开始时保留，续采不要覆盖 |
| `corpus/collection/<批次>/status.json`、`uncollected-destinations.json` | 进度汇总及尚未覆盖的候选条目 | 运行该批次的 `status.py` 刷新，非实时 |
| `corpus/collection/<批次>/coverage.json`、`audit.json`、`file-manifest.json` | 覆盖依据、完整性校验及文件清单 | 校验时生成的快照，非实时 |

**两种入口的记录能力不同**：仓库中的 `tools/guide-pipeline/pipeline.py` 维护全库索引并输出终端日志；上述批次目录来自本地扩采脚本，并非普通入口每次运行都会生成。批次脚本和计划随 `corpus/` 保存，不在 Git 中；仅拉取代码无法恢复它们。北京旅游网补充采集也是本地批次能力，不是普通入口的 `--source` 选项。

### 如何查看当前进度

在保存语料的仓库根目录执行以下 PowerShell 命令。先列出批次，结合名称和事件时间选择需要查看的一轮；不要把不同批次的汇总直接相加。

```powershell
Get-ChildItem .\corpus\collection -Directory | Select-Object Name
$batch = '.\corpus\collection\<批次目录名>'  # 替换为上一步列出的实际目录
Get-Content "$batch\events.jsonl" -Tail 20 -Encoding utf8
& .\tools\guide-pipeline\.venv\Scripts\python.exe "$batch\status.py"
Get-Content "$batch\uncollected-destinations.json" -Encoding utf8
```

`status.py` 读取索引、计划、批次基线与事件，更新本地汇总，不访问平台。只支持带有该脚本及配套文件的批次；不要在没有语料的 feature worktree 中运行。快照时效可结合文件修改时间和事件末尾时间判断。

统计口径：`total_records` 是全库原文条数，`new_records` 是相对该批次基线的差额（共享语料库后来入库的内容也会计入）；`detail_attempts` 包含失败请求，不等于入库量。`covered_catalogue_entries` 是已覆盖的候选条目数，`covered_destinations` 是按该批次别名规则合并后的目的地数。它们都不表示已导入应用的目的地数量，也不表示已完成适龄评估或内容加工。

待采列表表示候选条目还没有对应入库记录；未尝试、空结果和失败的区别要查 `events.jsonl`。媒体缺失或超限查看单条 `meta.json` 中的 `skipped_reason`。校验报告是生成时的结果；本地 `audit.py` 可能依赖特定迁移归档、统计口径，并会覆盖报告，重跑前先检查其依赖及已有人工补充字段。

### 如何判断停止、接着采集

先查看事件中的 `blocked`、`stopped`、`worker_failed` 和结束记录，确定停止原因；`worker_done` / `job_done` 表示运行结束，不保证队列全部成功或目标达成。`running.lock` 文件可能在退出后保留，不能仅凭文件存在判断进程仍在运行。

本地扩采脚本支持按索引跳过已有内容，但不是自动定时服务：

- `STOP` 文件要求批次停止。续采前先读取其内容和日志，确认是目标完成、人工暂停还是其他原因，再决定恢复原批次或准备新批次；不要直接删除停止标记后盲目重跑。
- 遇访问限制、验证页或连续空结果时保守停源；空结果不等于已确认触发反爬。先核实原因，必要时人工恢复登录，不对抗平台限制。当前批次脚本会跳过当天已有 `blocked` 事件的 UGC 源。
- 当前扩采以覆盖面为目标，某源在某组已有记录即可跳过，并不自动补足每组上限。脚本还会跳过该批次历史上已尝试的 UGC 内容及已记为未填充的目的地；失败和空结果不会隔天自动重试，应保留旧日志，另行准备有明确队列和限额的重试批次。
- 切换批次不应重置当天请求预算。新批次开始前汇总当天各批次的尝试记录；目前没有跨批次统一额度账本。也不要让多个进程同时写同一个语料库：批次内写锁不保护其他批次或普通入口。
- 持续扩大候选范围或补采不同来源时保留全库索引、出处、限速和组限额，只存原文。备份、换机时连同 `corpus/collection/` 一起搬运，具体步骤见 [操作手册：攻略语料库迁移](操作手册.md#攻略语料库迁移换机继续采集)。
