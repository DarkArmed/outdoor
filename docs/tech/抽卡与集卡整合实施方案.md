# 抽卡与集卡整合实施方案

> 版本：v1.0 ｜ 日期：2026-11-25 ｜ 状态：**方案已编写，尚未实施**
> 关联需求：[PRD-009 · 目的地抽卡、打卡与集卡](../card-collection/PRD-009-目的地抽卡与集卡.md)
> 本文只描述整合方案，不表示数据库、API 或正式页面已经交付。

## 0. 方案摘要

首期只整合已确认的“户外大冒险”明快卡通原型，其余四套继续作为设计候选，不建设主题切换系统。

采用“两个新页面 + 复用现有出行详情页”的整合方式：

- `/draw`：完成候选、洗牌、翻牌、重新抽卡和目的地揭晓。
- 现有 `/plan/:id?trip=:tripId`：继续负责装备、任务、安全说明和长按打卡。
- `/collection`：完成主动入册、筛选、查看历史卡和收藏统计。

后端新增抽卡会话与家庭收藏，不另建一套出行、打卡或徽章系统。现有 `Plan → Trip → Checkin → BadgeUnlock` 链路保持主责不变，收藏只能由当前账号在有效打卡后主动创建。

首期不新增运行依赖、第三方服务或常驻容器，继续使用 React/Vite、FastAPI、SQLAlchemy/Alembic 和 PostgreSQL。

## 1. 现状与整合边界

| 已有能力 | 当前实现 | 整合方式 |
|---|---|---|
| 公共方案 | `backend/app/models.py` 的 `Plan`；`backend/app/routers/plans.py` | 增加抽卡资格与卡片元数据，不复制方案。 |
| 用户出行 | `Trip`、`snapshot_plan()`、`POST /api/trips` | 抽中后仍通过现有 Trip 创建入口，保留快照和覆盖值。 |
| 装备与任务 | `GearState`、`TaskState`、`PersistedChecklist` | 不在抽卡页重新实现，继续由出行详情页负责。 |
| 打卡与徽章 | `POST /api/trips/{trip_id}/checkin`、`award_badges()` | 打卡不自动入册；收藏是独立、显式动作。 |
| 成就与足迹 | `BadgeWall`、`FootprintMap`、`BadgeDrawer` | 保留原语义，新增独立收藏册，不混用统计口径。 |
| 用户画像 | `Profile.child`、`Profile.prefs` | 服务端筛选候选和生成动态标题，不在代码中写死小名。 |
| 账号与缓存 | JWT、`get_current_user`、按 token 隔离的 SWR | 所有新读写均要求登录；退出时清除本机私密队列。 |
| 原型与照片 | `docs/card-collection/` | 迁移交互与授权照片，不迁移演示账号、演示收藏或 localStorage。 |
| 部署 | 单应用镜像 + PostgreSQL | 沿用镜像、迁移、备份和本机验证流程，不增加服务。 |

### 明确不做

- 不把五套原型全部产品化，不做主题切换和统一“主品牌”替换。
- 不做公开抽卡广场、评论、分享、家庭排名、付费抽卡、稀有度或连续签到。
- 不用抽卡结果替代天气、开放状态、体能、装备和家长判断。
- 不自动收藏、不自动排期、不用计划数冒充完成数。
- 不将原型 `adventure-album-v1` 等演示数据导入真实账号。
- 不默认回填历史 Trip 为收藏卡；历史内容如需入册，后续另做可预览的显式迁移。
- 不引入实时 GPS 轨迹、家庭地址、精确位置历史或新的地图服务。
- 不将原型目录整体暴露为生产静态站点；历史原型继续只作设计资料。

## 2. 目标页面与调用关系

```mermaid
flowchart TD
    U[孩子 / 家长] --> D[/draw]
    D --> DS[DrawSession API]
    DS --> P[Plan + Profile]
    D --> T[现有 POST /api/trips]
    T --> PD[/plan/:id?trip=:tripId]
    PD --> G[装备 / 任务 / 安全]
    PD --> C[现有 Checkin API]
    C --> B[现有 BadgeUnlock]
    PD --> CC[主动 Collect API]
    CC --> A[/collection]
    DS --> DB[(PostgreSQL)]
    T --> DB
    C --> DB
    CC --> DB
```

### 页面职责

- **抽卡页**只回答“下次去哪里”，不承担完整出行编辑。
- **出行详情页**继续回答“怎么去、带什么、怎么安全完成”。
- **收藏页**只展示服务端确认的真实完成记录，不展示抽中但未出行的卡片为已收藏。

## 3. 正式用户流程

| 阶段 | 页面与动作 | 系统结果 |
|---|---|---|
| 1. 发起 | 首页或 `/draw` 点击“快乐出发” | 服务端按画像与审核状态生成新的 `DrawSession`。 |
| 2. 洗牌 | 观看或跳过动画 | 展示本次保存的三个不同 Plan，动画期间禁止翻牌。 |
| 3. 翻牌 | 点击任意一张卡背 | 首次选择成功；三张都展示正面，选中卡高亮，其余保持半透明且不可改选。 |
| 4. 揭晓 | 查看真实风景、活动、强度和安全提示 | 可进入现有出行详情，或点击“重新抽卡”创建全新会话。 |
| 5. 准备 | 在现有详情页确认装备、任务、撤退和安全事项 | 创建/读取当前账号 Trip；翻牌本身不自动创建 Trip。 |
| 6. 打卡 | 家长确认到达并长按 | 复用现有 Checkin 和徽章事务；可记录待同步状态，但不直接入册。 |
| 7. 入册 | 用户主动点击“收进快乐收藏册” | 服务端确认 Trip 归属及有效 Checkin 后创建/更新收藏。 |
| 8. 回顾 | 筛选、打开历史卡 | 查看首次收藏快照、最近完成日期和 revisit 次数。 |

### 抽卡交互约束

- “再转一次”只重播动画，不改变当前 `DrawSession`。
- “重新抽卡”使用新的 `client_draw_id` 创建新会话，清空当前未提交的页面选择，不删除 Trip、Checkin 或收藏。
- 不设置“上一步”按钮。用户通过明确的“重新抽卡”改变选择，避免返回后误用旧结果。
- 首次选择后，三张卡均展示正面；未选中的卡不得仅凭视觉消失。
- 刷新页面从 `/api/draws/current` 恢复当前会话，不使用原型 localStorage 作为真实状态源。
- 动画支持 `prefers-reduced-motion`、键盘和真实触控；动画结束不是保存成功提示。

## 4. 数据模型调整

以下均为拟新增结构，正式编码前同步更新 `docs/tech/数据契约.md` 与 PRD-009 的对应状态。

### 4.1 `plans` 增加抽卡元数据

| 字段 | 类型 | 默认值与用途 |
|---|---|---|
| `draw_eligible` | Boolean | 默认 `false`；只有审核通过的公共方案可进入候选池。 |
| `card_version` | Integer | 默认 `1`；卡片展示版本，只有内容审核变更时递增。 |
| `card` | JSON | 卡片展示、筛选与安全约束的公共元数据。 |

`card` 建议结构：

```json
{
  "cover_type": "photo",
  "cover_asset": "/card-assets/yanqi-lake.webp",
  "cover_alt": "真实景观的准确替代文本",
  "cover_source": "Wikimedia Commons 来源页",
  "cover_license": "CC BY-SA 4.0",
  "region": "北京 · 怀柔",
  "activity_tags": ["看湖光", "远观小鸟", "找颜色"],
  "activity_type": "hike",
  "difficulty": 1,
  "distance_text": "4–5 km",
  "distance_km": 5,
  "drive_hours": 1.5,
  "min_age": 5,
  "safety_summary": "湖边不下水；孩子走前、大人断后。",
  "reason": "面向孩子的短推荐理由"
}
```

规则：

- `archived=false`、`draw_eligible=true`、`card` 必填项完整，三者缺一不可。
- `card` 只含可公开内容，不含家庭画像、家庭路线、私人备注或精确轨迹。
- `distance_km`、`drive_hours` 用于筛选，不解析展示字符串猜测数值。
- 现有 `type/theme/emoji` 继续服务原计划卡片和插图，不与收藏主题混用。

### 4.2 `draw_sessions`

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | Integer 主键 | 服务端生成。 |
| `user_id` | FK → users.id | 必填、索引，账号隔离。 |
| `client_draw_id` | String(64) | 客户端每次主动抽卡生成；与 `user_id` 联合唯一，防网络重试重复建组。 |
| `candidate_plan_ids` | JSON | 本次三个不同 Plan；不足三个时保存实际数量。 |
| `shuffled_plan_ids` | JSON | 洗牌后的展示顺序，与候选数量一致。 |
| `selected_plan_id` | String，可空 | 必须属于 `candidate_plan_ids`，首次选择后不可改。 |
| `created_at` | DateTime | 创建时间。 |
| `selected_at` | DateTime，可空 | 首次有效选择时间。 |

`selected_plan_id` 可以为空，但不得指向不存在的 Plan。删除公共内容时优先退役，不做破坏历史引用的物理删除。

### 4.3 `trips` 关联抽卡会话

新增可空 `draw_id`（FK → draw_sessions.id，唯一）。

- `TripCreate` 增加可选 `draw_id`。
- 提交时必须验证会话属于当前账号、已选择且 `selected_plan_id == TripCreate.plan_id`。
- 一个会话最多关联一个 Trip；重复提交返回已有 Trip，不重复创建。
- 未传 `draw_id` 的现有创建方式保持兼容。
- `snapshot_plan()` 同步纳入 `card/card_version`；首次收藏从 Trip 快照生成 `card_snapshot`，不读取最新 Plan 覆盖历史卡。

### 4.4 `card_collections`

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | Integer 主键 | 服务端生成。 |
| `user_id` | FK → users.id | 必填、索引。 |
| `plan_id` | FK → plans.id | 与 `user_id` 联合唯一。 |
| `card_version` | Integer | 首次收藏时的版本。 |
| `card_snapshot` | JSON | 首次收藏时的完整公共卡片快照，不被后续封面更新静默覆盖。 |
| `first_checkin_id` | FK → checkins.id | 首次有效打卡。 |
| `last_checkin_id` | FK → checkins.id | 最近有效打卡。 |
| `revisit_count` | Integer | 默认 `0`；首次之后的每个不同 Checkin 才递增。 |
| `created_at` / `updated_at` | DateTime | 创建与最近更新时间。 |

### 4.5 `collection_checkins`

用于保证入册幂等：

| 字段 | 约束 |
|---|---|
| `collection_id` | FK → card_collections.id，索引。 |
| `checkin_id` | FK → checkins.id，**唯一**。 |
| `client_action_id` | String(64)，与 `collection_id` 联合唯一，支持弱网重试。 |
| `created_at` | 入册时间。 |

同一个 Checkin 只能影响一个收藏一次；不同 Trip/Checkin 才能推进 `last_checkin_id` 和 `revisit_count`。

### 4.6 `checkins` 的幂等补充

- 为 `trip_id` 增加唯一约束，防止并发打卡生成两条记录。
- 增加可空 `client_checkin_id`，与 `trip_id` 联合唯一，支持弱网重放。
- 迁移前先审计重复 `trip_id`；存在重复时停止并人工核对，不自动删除历史。

## 5. API 设计

所有新接口都要求 `get_current_user`，任何 `user_id` 都以 JWT 中的账号为准，不能由请求体指定。

### 5.1 抽卡

| 方法与路径 | 行为 |
|---|---|
| `POST /api/draws` | 请求 `{client_draw_id}`；生成并返回会话和卡片。相同幂等键返回原会话。 |
| `GET /api/draws/current` | 返回当前账号最近会话；无记录时返回 204 或明确的空状态。 |
| `GET /api/draws/{id}` | 仅返回属于当前账号的指定会话；其他账号返回 404。 |
| `POST /api/draws/{id}/select` | 请求 `{plan_id}`；事务内锁定会话，验证候选和首次选择，返回完整会话。 |

`POST /api/draws` 不接收候选 ID 列表，避免客户端绕过画像或审核规则。重复选择同一 Plan 可返回当前结果；选择不同 Plan 返回 409。

### 5.2 创建出行

继续使用 `POST /api/trips`，扩展 `TripCreate.draw_id`。服务端在创建前校验抽卡会话与 Plan 匹配，然后调用共享的快照创建逻辑，避免网页原流程和抽卡流程产生两份实现。

### 5.3 收藏

| 方法与路径 | 行为 |
|---|---|
| `GET /api/collections` | 返回当前账号的收藏卡与统计，支持按 `activity_type` 筛选。 |
| `GET /api/collections/{id}` | 返回当前账号的一张历史卡，其他账号返回 404。 |
| `POST /api/trips/{trip_id}/collect` | 请求 `{client_action_id}`；验证归属和有效 Checkin，幂等创建或更新收藏。 |
| `GET /api/collections/stats` | 返回不同目的地数、revisit 总数和有效完成里程；可选并入列表响应减少请求。 |

`POST /api/trips/{trip_id}/checkin` 保持现有语义，不因参数变化自动入册。若未来需要“打卡并直接入册”，必须新增显式参数且默认仍为 `false`，不能改变旧客户端行为。

### 5.4 事务顺序

入册操作在一个数据库事务内完成：

1. 按当前账号读取并锁定 Trip 和 Checkin。
2. 验证 Checkin 属于该 Trip，且不是伪造的 Plan/用户组合。
3. 创建或读取 `(user_id, plan_id)` 对应的收藏。
4. 写入唯一的 `collection_checkins`。
5. 若是新 Checkin，更新 `last_checkin_id`；非首次时递增 `revisit_count`。
6. 提交后返回真实收藏状态，再播放“已收入”动画。

唯一约束冲突应按幂等结果处理，不可笼统报成系统错误。提交失败不得显示已收藏。

## 6. 候选、筛选与随机规则

1. 从 `archived=false AND draw_eligible=true` 且卡片完整的 Plan 开始。
2. 用当前账号 `Profile.child/prefs` 过滤：
   - `min_age` 高于当前年龄时不推荐。
   - `drive_hours` 超过 `maxDriveHoursOneWay` 时不推荐。
   - `distance_km` 超出 `child.enduranceKm` 上限时不推荐。
   - `activity_type` 与明确禁忌冲突时不推荐。
3. 画像缺失或字段无法判断时，使用保守审核池；不能把全部公共方案视为适龄。
4. 未收藏数不少于三个时，优先从未收藏中抽取；不足时允许其他目的地补位并标记“再去一次”。
5. 使用 Python `secrets.SystemRandom` 采样并 Fisher–Yates 洗牌。目标是无重复、顺序可变，不承诺密码学抽签或防猜。
6. 候选不足三个时展示实际数量；为空时提示调整画像或等待内容审核，不复制卡片凑数。

候选生成、筛选、补位和洗牌放在独立服务模块，便于注入固定随机源测试，不散落在路由中。

## 7. 前端整合

### 7.1 路由与入口

在 `web/src/App.tsx` 的 `RequireAuth` 内新增：

- `/draw` → `CardDrawPage`。
- `/collection` → `CollectionPage`。

在 `HomePage` 的 hero 增加“开始抽卡”主入口；在 `Layout` 和成就面板提供“快乐收藏册”入口。收藏不替换现有徽章墙和足迹地图。

### 7.2 建议组件

| 组件 | 职责 |
|---|---|
| `CardDrawPage` | 管理 `idle / shuffling / picking / revealed / error` 状态和页面阶段。 |
| `ShuffleDeck` | 动画、跳过、重播、键盘与减少动态效果。 |
| `DestinationCard` | 真实照片、地区、活动标签、强度、安全和已选择状态。 |
| `DrawActions` | 开始、重新抽卡、查看目的地，清晰区分动画重播与新会话。 |
| `CollectionPage` | 筛选、统计、空状态和错误重试。 |
| `CollectionCard` | 首次收藏快照与详情，不读取其他账号数据。 |
| `CollectCardButton` | 在现有出行详情页主动入册，处理待同步和服务端确认。 |

样式从确认版原型提炼为 `card-collection.css`，继续使用原网站的天空蓝、太阳黄、草绿、珊瑚色、大圆角和亲子插图。其余四套原型不进入正式主题配置。

### 7.3 API 与状态

- `api/client.ts` 增加 draws/collections 请求，沿用现有 Axios 实例和 401 处理。
- `api/types.ts` 从更新后的 OpenAPI 类型生成，不手写重复响应类型。
- `useApi.ts` 增加 `useCurrentDraw`、`useCollections`，key 包含当前用户 ID。
- `PlanDetailPage` 在有效打卡后展示 `CollectCardButton`，成功后导航 `/collection`。
- 抽卡选择、Trip、打卡和收藏写入成功后分别使相关 SWR key 失效；写成功后的辅助读取失败不得误报未保存。
- 动态标题使用 `Profile.child.name`，缺失时使用通用“小小探险家”，不读取配置文件或写入真实小名。

## 8. 图片与内容资产

- 将经过授权的优化 WebP 放入 `web/public/card-assets/`，同时提供 `ATTRIBUTION.md`。
- 原始 JPG 和原型参考材料保留在文档资料目录；正式前端只加载所需优化图。
- 图片必须对应真实目的地，记录作者、来源、许可、替代文本和裁切方式。
- 卡通插图只用于界面装饰、人物、卡背和庆祝反馈，不替代目的地照片。
- 内容导入沿用显式审核流程，不将 `corpus/`、未授权第三方图片、家庭配置或路线原始数据打包进 dist。
- 现有 `tools/dump-data.js` 后续扩展卡片元数据导出与校验；运行时应用不依赖 Node 或仓库全量目录。
- `backend/app/static_site.py` 需显式增加只读 `/card-assets` 挂载和 `/draw`、`/collection` 的 GET/HEAD 页面路由；不存在的资源继续返回 404，不能回退为 index。

## 9. 数据迁移与历史兼容

新建 Alembic 修订（建议 `20261125_card_collection`），父级为当前合并 head `20261003_merge_web_wechat`：

1. 为 Plan 增加 `draw_eligible/card_version/card`。
2. 创建 `draw_sessions`、`card_collections`、`collection_checkins`。
3. 为 Trip 增加 `draw_id`。
4. 为 Checkin 增加 `client_checkin_id` 和唯一约束。
5. 迁移前检查重复 Checkin、缺失引用和现有 Trip/Plan 主键。

兼容规则：

- 现有 Plan 默认 `draw_eligible=false`，经内容包显式启用，不自动开放整个方案库。
- 现有 Trip、GearState、TaskState、Checkin、BadgeUnlock 和 LegacyImport 保留，不改历史快照。
- 不为历史打卡自动创建收藏；原型演示数据也不创建真实收藏。
- 老 Trip 缺少卡片元数据时，页面使用现有内容回退；首次新收藏必须存在完整、可审核的卡片快照。
- 不把 `alembic downgrade` 作为生产回退手段；恢复依赖变更前备份与确定镜像。
- 备份、恢复和统计校验必须包含新增表及其外键。

## 10. 弱网、离线与隐私

### 抽卡

- 新抽卡要求在线，因为候选和随机由服务端生成；离线时显示当前已缓存会话的只读内容和重试提示。
- 网络失败使用相同 `client_draw_id` 重试，不能反复创建新组。
- 切换账号后不能恢复上一个账号的会话。

### 打卡与入册

使用账号隔离的本地待同步队列（建议 `outdoor:offline-actions:{userId}`，用浏览器原生存储实现，不增加库）：

```json
{
  "action_id": "客户端生成的 UUID",
  "type": "checkin | collect",
  "trip_id": 123,
  "created_at": "客户端记录时间",
  "status": "pending"
}
```

- 页面明确区分“本机待同步”和“服务端已确认”。
- 恢复网络后按 `checkin → collect` 顺序提交，服务端用幂等键去重。
- 401 时保留队列并要求重新登录；其他账号不得读取该队列。
- 退出账号时提示未同步数量并清除本机私密队列，不删除服务端历史。
- 不记录家庭地址、精确轨迹或持续定位。首期采用家长到达确认；coarse 位置辅助另行评审，不能成为打卡硬门槛。

## 13. 验收清单

### 后端

- 候选过滤、空池、少于三个、未收藏优先、重复目的地标记。
- 同组无重复，重试幂等，多指/并发选择只能有一个结果。
- 会话越权、Trip 越权、收藏越权均不可读取或写入。
- `draw_id` 与 Plan 不匹配时拒绝创建 Trip，重复创建返回原 Trip。
- 未打卡不能入册；同 Checkin 重试不增加 revisit；不同 Checkin 正确更新。
- 历史卡片快照不随 Plan 后续编辑变化，徽章和旧统计不重复计算。
- 空库与现有数据库迁移通过，迁移前重复 Checkin 审计有明确结果。

### 前端

- 洗牌期间不可翻牌，跳过后直接可选，重播不改变会话。
- 选中后三张均展示正面，其他两张保持半透明且不可改选。
- 重新抽卡清空未提交选择，不删除收藏；刷新恢复同一服务端会话。
- 未保存成功不播放成功反馈；写入成功后的辅助读取失败不误报失败。
- 320/390px 手机、桌面、键盘、真实触控、减少动态效果和直接深链接通过。
- 小名从当前画像读取，退出后不能看到上一账号的抽卡或收藏。
- 图片失败有文字回退，真实照片与授权信息可追溯。

### 端到端

至少使用两个测试家庭完成：

1. A 家庭抽卡、选择、创建 Trip、打卡、主动入册、刷新查看。
2. B 家庭不能读取 A 的会话、Trip、打卡和收藏。
3. A 重复入册不产生重复卡，第二次不同 Trip 正确累计 revisit。
4. 断网后打卡/入册显示待同步，恢复后不重复提交。
5. 容器重建后抽卡、Trip、收藏和新迁移数据均保留。

## 14. 默认决策与后续复议点

| 事项 | 本方案默认值 | 何时复议 |
|---|---|---|
| 正式主题 | 只整合户外大冒险 | 孩子试用明确需要其他表达，再逐套评审。 |
| 收藏触发 | 有效打卡后用户主动入册 | 真实试用证明额外点击负担明显，再讨论默认勾选，不静默改变。 |
| 历史数据 | 不回填收藏 | 用户明确要求后，提供可预览、可撤销的迁移方案。 |
| 到达确认 | 家长确认，不强制定位 | 位置误用影响真实性且隐私评审通过后再评估 coarse 辅助。 |
| 抽卡可用性 | 新抽卡在线，缓存会话只读 | 确有高频离线抽卡需求后，再设计签名候选包。 |
| 基础设施 | 不新增依赖、服务或容器 | 实际容量或安全需求变化且用户允许后，另立 ADR。 |
| 访问范围 | 受邀家庭，不自动公开 | HTTPS、访问控制、备份和试用验收全部完成后。 |
