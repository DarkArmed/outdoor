# 操作手册（SOP）

> 版本：v2.2 ｜ 日期：2026-10-08

## 运行前后端

准备 Node.js 22.12+、Python 3.11+。后端在 `backend/` 执行：

```sh
python -m venv .venv
# Windows PowerShell: .venv/Scripts/Activate.ps1
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

编辑 `.env`，本地可设 `DATABASE_URL=sqlite:///./outdoor.db`；部署使用 PostgreSQL，并配置独立 `SECRET_KEY`。随后：

```sh
alembic upgrade head
python -m app.seed
uvicorn app.main:app --reload
```

种子脚本需要 Node，读取 `data/`，只插入缺失公共记录；已有记录不会被覆盖。它保留历史默认账号初始化行为（`default@outdoor.local` / `outdoor`），可导入本地 `config/profile.json`。新用户可直接在网页注册独立账号。

另开终端在 `web/` 执行：

```sh
npm ci
npm run dev
```

打开 `http://localhost:5173`。Vite 将 `/api` 转发到 `http://localhost:8000`；可通过 `VITE_API_PROXY_TARGET` 改后端地址。API 文档在 `http://localhost:8000/docs`。生产构建运行 `npm run build`，静态服务器需支持 SPA 路由回退，并把 `/api` 转发到后端。

## 网站使用

注册/登录 → 首页选方案 → 创建本次出行 → 勾选装备与任务 → 长按两秒打卡。清单保存后刷新保留；画像页编辑家庭信息；我的出行页可修改名称、日期或删除。退出后可登录另一账号。

## 导入旧站浏览器记录

同地址的记录在登录后自动导入。不同域名或 `file://` 旧站的 localStorage 无法由新站直接读取：在**原来打开旧站的浏览器页面**控制台执行以下命令，复制返回 JSON，在新站「家庭画像 → 导入旧站记录」粘贴导入。

```js
JSON.stringify(Object.fromEntries(Object.keys(localStorage)
  .filter(k => /^(gear|tasks):/.test(k) || ['plans:done', 'badges:unlocked'].includes(k))
  .map(k => [k, localStorage.getItem(k)])))
```

旧站文件可从 Git 历史 `9d669c4` 找回。导入保留原始数据；同一浏览器中的相同载荷只归属首次导入账号，后端重试回执避免重复创建。未知方案或损坏数据会拒绝整批导入并提示，可修正后重试。

## 新增方案与路线维护

1. 复制 `plans/周计划模板.md`，包含必带装备清单，更新赛季索引。
2. 在 `data/data-a|b|c|d.js` 添加方案。运行种子脚本导入新增记录。
3. 路线流水线配置：复制 `tools/route-pipeline/config.example.json` 为同目录 `config.json`，填高德 Key；复制 `config/profile.example.json` 为 `config/profile.json`，配置路线起点。两者均不入 Git。
4. 在 `tools/route-pipeline/` 执行 `node pipeline.js <planId>`；省略 id 为全量，`--network` 刷路网。输出 `data/routes.js` 与 `data/network.js`。`node mock.js` 仅用于示例，会覆盖路线文件。
5. 在网页核对方案、路线、清单。流水线更新已有数据后，当前 seed 不覆盖已入库记录，需由维护者更新公共表；用户 Trip 快照保留。

网页画像以各账号数据库记录为准。`config/profile.json` 用于种子默认画像及离线路线流水线，已移除 `sync-profile.js`。

## 测试与类型生成

在仓库根运行 `python -m pytest -q`。在 `web/` 运行：

```sh
npm run test -- --run
npm run lint
npm run build
npx playwright install chromium
npm run test:e2e -- --workers=2
```

浏览器测试自动启动 8015 后端与 5175 前端，不复用已有服务；使用临时 SQLite，不访问开发数据库。Python 环境需已安装后端依赖。报告在 `web/playwright-report/`，截图在 `web/test-results/`。

后端运行时执行 `npm run generate:api` 更新类型；保留 `--empty-objects-unknown` 以正确生成 JSON 扩展字段。

## 攻略语料库迁移（换机继续采集）

迁移 = 整目录搬运 + 目标机重建运行环境。日常进度查询、暂停原因和续采限制见 [攻略流水线：持续采集](攻略流水线.md#七持续采集进度入口与续采)，数量以本地索引和日志为准，无需逐轮更新文档。本地批次辅助脚本可能依赖原机器上的归档路径，迁移后运行前需检查。

### 源机：打包带走的 3 样东西

| 内容 | 路径 | 作用 |
|---|---|---|
| 语料库 | `corpus/`（整目录，含 `index.jsonl` 和 `collection/`） | 全部原文与媒体；索引用于去重/限额，批次目录保存计划、日志、快照及本地脚本。漏掉索引会导致重复请求，漏掉批次目录会丢失续采上下文 |
| 采集配置 | `tools/guide-pipeline/config.json` | 关键词分组、视频阈值、限额（gitignore，git 里没有） |
| 登录态 | `tools/guide-pipeline/.cookies/` | 小红书 cookie，避免重新扫码（gitignore） |

通用流水线代码在 git master 上，目标机拉代码即有；本地批次脚本随 `corpus/collection/` 搬运。局域网共享用 robocopy（断点续传）：

```bat
robocopy D:\Repos\outdoor\corpus \\目标机\共享\corpus /E /Z /R:3 /W:5
robocopy D:\Repos\outdoor\tools\guide-pipeline \\目标机\共享\gp-local config.json /Z
robocopy D:\Repos\outdoor\tools\guide-pipeline\.cookies \\目标机\共享\gp-local\.cookies /E /Z
```

### 目标机：恢复与验证

```sh
git clone <仓库地址> && cd outdoor        # 或已有仓库 git pull --ff-only
cd tools/guide-pipeline
python -m venv .venv
# Windows bash: .venv/Scripts/python.exe -m pip install -r requirements.txt
# macOS/Linux:  .venv/bin/python -m pip install -r requirements.txt
.venv/Scripts/python.exe -m playwright install chromium
```

然后把 `corpus/` 放到仓库根（与 `tools/` 同级），`config.json` 和 `.cookies/` 放回 `tools/guide-pipeline/`。先按上述进度查询入口检查索引、日志并刷新批次快照（不联网）。如需验证真实采集入口，可运行以下命令；**该命令可能访问平台并下载新内容，不是离线检查**：

```sh
.venv/Scripts/python.exe pipeline.py --source weibo --keyword 白河湾 --max 1
```

输出 `[dup] 跳过已存在` / `[skip] 组已满额` 可验证对应条目的去重或对应组的限额判断，不能替代全库完整性校验。续采前仍需检查批次停止原因与当天已用额度。

### 收尾与注意

- 目标机验证通过后，源机可删 `corpus/` 释放磁盘。
- 小红书 cookie 换机可能失效（平台校验环境），表现为采集报「触发登录墙」；在目标机重跑一次 `pipeline.py --source xhs --login` 扫码即可（需人在场，扫的是脚本弹出的 Chromium 窗口）。
- 浏览器面板（如 Kimi/Chrome）里的登录态与流水线 cookie 互不相通，只认 `tools/guide-pipeline/.cookies/xhs.json`。
