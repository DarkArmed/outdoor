# 容器化本机验证

> 版本：v1.0 ｜ 日期：2026-10-04

本次以 master `c160d9f` 为基线，实现并验证本机容器部署。复用既有 React/Vite、FastAPI/Uvicorn 和 PostgreSQL，未修改 npm/pip 依赖清单。采用一个应用容器和一个数据库容器；迁移和示例数据导入是一次性作业。

## 结果与范围

本机入口为 <http://127.0.0.1:18080>，用户可直接注册新账号。只有一条“容器验证示例（虚构）”，不包含实际家庭画像、路线或活动建议。验证结束后主站点继续运行，独立恢复演练环境已清理。

这是**本机验收配置，不是公网生产发布**。本轮没有实现公共内容通用导入、数据库角色分权、自动备份调度、HTTPS 或公网发布；不据此宣称规划中所有生产验收项已完成。当前已实现机制以本文件为准。

## 文件与运行机制

- 根目录 `Dockerfile`：Node 构建阶段执行既有 `npm ci` / `npm run build`，Python 阶段安装原 requirements，复制后端、迁移和 dist，以非 root 用户启动 Uvicorn。
- `.dockerignore`：只允许所需 web/backend 源文件，不传入个人配置、原始路线、其他 worktree、数据库或本地验证产物。
- `deploy/compose.yaml`：固定默认项目名 `outdoor-local`；db 健康后运行 migrate，迁移成功后启动 app；demo 仅在显式调用时运行。
- `deploy/prepare-local.py`：用 Python 标准库生成随机数据库密码与 JWT 密钥，写入忽略的 `deploy/.env.local`；已有文件保持原样，控制台不输出秘密。
- `deploy/verify-local.py`：只允许 loopback URL；exercise 创建虚构账号并写状态，verify 使用同一账号验证重建/恢复后的持久性。
- `web/playwright.container.config.ts`：直接访问 18080，不启动 Vite/SQLite 测试服务；容器用例与现有 E2E/Vitest 分开。

`APP_ENV=production` 关闭自动建表、旧 seed 和公开 API 文档，要求显式 PostgreSQL、足够长的独立 JWT 密钥，以及存在的 `STATIC_DIR`。开发默认模式保持原行为。`DATABASE_URL_FILE` / `SECRET_KEY_FILE` 可读文件秘密，同名明文与文件配置不能同时给；本机 Compose 实际使用随机环境变量配置，并未配置 secrets 挂载。

FastAPI 显式提供现有网页 GET/HEAD 路由，`/assets` 只提供真实构建文件。未知网页/API/静态文件仍返回 404，不把 API 错误替换成 index。`/api/ready` 连接真实数据库并核对镜像携带的 Alembic heads；`/api/health` 只表示进程存活。生产模式要求静态产物，但迁移作业本身不会启动 Web 应用。

## 启动与复验（PowerShell）

在包含本次实现的 worktree 根目录执行。需要已安装并运行 Docker Desktop 的 Linux engine 和主机 Python；浏览器测试另使用项目既有 Node/Playwright。

```powershell
# Docker 不在 PATH 时，兼容本机用户目录安装位置。
$docker = (Get-Command docker -ErrorAction SilentlyContinue).Source
if (-not $docker) {
    $docker = Join-Path $env:LOCALAPPDATA 'Programs\DockerDesktop\resources\bin\docker.exe'
}
$dc = @('compose', '--env-file', 'deploy/.env.local', '-f', 'deploy/compose.yaml')

python deploy/prepare-local.py
& $docker @dc config --quiet
& $docker @dc build app
& $docker @dc up -d --wait app
& $docker @dc run --rm demo
python deploy/verify-local.py exercise

npm --prefix web ci
Push-Location web
npx playwright test --config playwright.container.config.ts
Pop-Location
```

每条命令成功后再继续；若缺浏览器运行时，按原项目 Playwright 安装方式准备 Chromium。无需安装新 Web 服务或新增依赖项。更改端口可编辑 `deploy/.env.local` 的 APP_PORT；验证脚本用 `--url` 匹配，浏览器配置的 baseURL 也需相应调整。

`exercise` 每次创建一组新的测试账号；重复检查已有数据应使用 `verify`。凭据只保存于忽略的 `deploy/local-artifacts/verify-state.json`，不需要手工把它贴到命令行或文档。

### 容器重建与停止

```powershell
& $docker @dc up -d --force-recreate --wait app db
python deploy/verify-local.py verify

# 停止服务但保留数据卷。
& $docker @dc stop
# 重新启动。
& $docker @dc up -d --wait app
```

不要通过删除卷进行普通重建。保留 project 名称和 `.env.local`；已有数据库卷的密码不会因重新生成环境文件自动更改。

### 备份与隔离恢复

以下只对本配置的虚构数据执行；恢复到另一个项目，不能替换主验证数据库。

```powershell
New-Item -ItemType Directory -Force deploy/local-artifacts | Out-Null
& $docker @dc exec -T db pg_dump -U outdoor -d outdoor -Fc -f /tmp/outdoor-local.dump
& $docker @dc cp db:/tmp/outdoor-local.dump deploy/local-artifacts/outdoor-local.dump
Get-FileHash -Algorithm SHA256 deploy/local-artifacts/outdoor-local.dump

# 先确认没有同名既有恢复项目；本次验证已清理它。
$env:APP_PORT = '18081'
& $docker @dc -p outdoor-local-restore up -d --wait db
& $docker @dc -p outdoor-local-restore cp deploy/local-artifacts/outdoor-local.dump db:/tmp/outdoor-local.dump
& $docker @dc -p outdoor-local-restore exec -T db pg_restore -U outdoor -d outdoor --no-owner --exit-on-error /tmp/outdoor-local.dump
& $docker @dc -p outdoor-local-restore up -d --wait app
python deploy/verify-local.py verify --url http://127.0.0.1:18081
Remove-Item Env:APP_PORT
```

恢复成功后，先核对 `outdoor-local-restore_pgdata` 的 Compose project 标签确为恢复项目，再仅清理该项目及其演练卷；主项目 `outdoor-local` 继续保留。本轮演练已按此核对后清理。不要使用全局 prune，也不要删除其他项目资源。

## 当前限制

- 仅用于本机、虚构数据；未配置 TLS、公网入口或微信真机的合法域名。
- 本机演练中 app 与迁移共用数据库初始化账号；生产前要落实最小权限角色，不能直接把此配置公开。
- 未设置自动异机备份、证书轮换、告警渠道；当前成功的是一次隔离恢复，不是已经达成持续 RPO/RTO 保证。
- 未导入仓库实际路线或家庭配置，未实现通用公共数据更新工具；demo 不覆盖已有同 ID 记录。
- 生产启动的错误校验、非 root、只读文件系统等已实现，但不代表原有依赖已完成全面安全审计。
- 静态与 API 共用进程，未进行吞吐压测、并发容量验证或不兼容 schema 回退演练。
