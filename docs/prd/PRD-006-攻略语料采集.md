# PRD-006-攻略语料采集

> PRD-006 · v0.1 · 2026-10-05 · 草稿

需求项状态：✅ 已实现 ｜ 🔨 待实现 ｜ ⚠️ 部分实现/待验证 ｜ ❌ 已取消

## 1. 背景与目标

当前 `plans/` 下的活动方案来源单一（均为 AI 规划生成），风格与地点逐渐重复。需要持续引入真实世界的户外攻略（小红书、微博、携程等平台上的亲子/京郊户外内容），作为后续生成多样化方案的素材库。

本期目标：**先把原文采下来、原样存好**，不急于定义标准化格式——标准化（提取地点/强度/季节/适合年龄等结构化字段）放到二期，等积累了足够语料看清内容形态后再定。

## 2. 需求项

### 2.1 数据源

2.1.1 🔨 首批数据源（按优先级）：

| 优先级 | 源 | 理由 |
|---|---|---|
| P0 | 微博（移动版） | 免登录可搜可读全文，户外博主内容多（含视频），实施成本最低 |
| P0 | 携程游记 | 免登录可读全文，自带结构化元数据（天数/花费/出行人类型/玩法）；注意：游记业务已公告 2025-11-30 停止运维，只有存量、无增量 |
| P1 | 小红书 | 攻略质量最高、最贴近"新手亲子"场景，但必须登录 + 浏览器自动化，实施成本与账号风险最高 |
| P2 | 马蜂窝 | 传统游记站，内容偏长途旅行，作为补充 |

2.1.2 🔨 数据源可按源独立启停；某一源失效（改版、风控升级）不应阻塞其他源。

### 2.2 采集方式

2.2.1 🔨 按关键词检索采集，关键词清单可配置（如「北京亲子徒步」「京郊露营」「北京遛娃 爬山」等）。
2.2.2 🔨 每条语料保存为**原文**：标题、正文全文、图片原图、视频、作者、发布时间、原文链接、互动数据（赞/藏/评，用于后续筛选优质内容）。
2.2.3 🔨 不做任何清洗、改写、摘要、格式标准化——保存即所见。
2.2.4 🔨 视频只下载**不超过 50MB** 的；超过阈值只保存封面图、视频直链（若可获取）和元数据。阈值可配置，50MB 为暂定值（依据：亲子户外短视频多在 15s–3min，平台压缩后通常 5–40MB）。
2.2.5 🔨 同一原文（同源同 ID）重复运行时不得重复下载媒体文件；正文元数据可刷新。

### 2.3 存储

2.3.1 🔨 语料保存在本地目录（不进 git，媒体文件体积大），目录结构按 `源/内容ID/` 组织，每条语料自包含（文字 + 图片 + 视频 + 元数据放同一目录）。
2.3.2 🔨 维护一份全局索引（源、ID、标题、关键词、采集时间、媒体数量），便于浏览和后续标准化时批量处理。
2.3.3 🔨 存储格式对二期标准化友好：文字与元数据用通用格式（Markdown + JSON），二期脚本无需重新下载即可处理存量语料。

### 2.4 合规与安全

2.4.1 🔨 语料仅供个人家庭活动规划参考，**不二次发布、不商用、不分发**；每条语料必须保留原文链接和作者信息作为出处。
2.4.2 🔨 采集必须限速（请求间隔、每日上限），避免对平台造成压力、降低封号风险。
2.4.3 🔨 登录凭据（cookie）只存本地、不进 git。
2.4.4 🔨 尊重 robots.txt 与平台条款；如遇明确反爬升级（滑块、封号警告），该源暂停而不是对抗升级。

## 3. 二期展望（本期不做）

- 标准化抽取：从原文提取目的地、强度、季节、适合年龄、交通方式等结构化字段，与现有 `data/data-*.js` 方案格式对齐。
- 语料筛选与评分：基于互动数据 + LLM 初筛优质攻略。
- 增量订阅：每周自动跑一轮关键词，新语料进「待读」队列。
