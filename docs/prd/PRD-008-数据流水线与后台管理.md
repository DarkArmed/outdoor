# PRD-008-数据流水线与后台管理

> PRD-008 · v0.9 · 2026-10-15 · 草稿

需求项状态：✅ 已实现 ｜ 🔨 待实现 ｜ ⚠️ 部分实现/待验证 ｜ ❌ 已取消

## 1. 背景与目标

攻略语料采集（PRD-006）目前靠手动跑脚本：无统一调度、无跨批次预算账本、采集状态不可见。INV-001 调研（小红书采集窗口规律）已用实验验证了可持续的采集节奏（每 24h 一轮、会话预算 25 请求、streak 后冷却递增），具备把采集升级为**生产级常驻数据流水线**的依据。

本期目标：

1. 流水线**常驻运行、动态调度**——作业按调度自动执行，运行中可启停、可改参数，无需人工挂脚本。
2. 流水线**可扩展**——本期只做「采集」阶段；架构上为后续「加工」「消费」阶段预留接入点，最终目标是自动生成户外计划模板。
3. 提供**仅管理员可登录的后台管理页面**，核心是数据流水线 dashboard，采集状态与预算用量一目了然。

## 2. 需求项

### 2.1 分阶段流水线架构

2.1.1 ✅ 流水线按「阶段」组织，阶段类型包括：collect（采集，本期实现）、process（加工，后续）、consume（消费，后续）、emit（生成户外计划模板，最终目标）。本期仅 collect 有实际逻辑，其余阶段预留注册接口。
2.1.2 ✅ 新数据源可注册加入采集阶段，不影响既有源；某一源失效或被暂停不阻塞其他源（沿用 PRD-006 2.1.2）。
2.1.3 ✅ 采集产物仍落入本地语料库 `corpus/`（沿用 PRD-006 2.3 的存储与格式约定，不进 git）。

### 2.2 常驻调度

2.2.1 ✅ 流水线 worker 为常驻服务，随容器编排启动；作业到期自动执行，无需人工触发。
2.2.2 ✅ 作业支持动态管理：暂停、恢复、立即触发、修改调度参数（周期、会话预算等），**生效无需重启服务**。
2.2.3 ✅ 小红书采集节奏按 INV-001 已验证规则执行：每 24h 一轮、每轮会话预算 ≤25 请求（搜索+详情合计）、预算内主动停止、不撞墙。
2.2.4 ✅ 某源触发「连续空搜索」保守暂停（streak）后：24h 内不再请求该源；再次发生则冷却时间按 2 倍递增，封顶 48h；冷却结束自动恢复。
2.2.5 ✅ 采集队列按各目的地历史尝试次数升序排列（没采过的优先，反复落空的沉底）。
2.2.6 ✅ 详情页失败率上升时提前收工（预算见底前兆，INV-001 规律 4）。
2.2.7 ✅ 请求预算按**全流水线统一账本**计量：任意作业、任意批次的请求都计入同一账本，24h 滑动窗口内不超各源限额；换作业、换批次不再出现预算口径断裂。

### 2.3 运行记录

2.3.1 ✅ 每次作业运行有记录：开始/结束时间、结局分类（clean / budget_stop / streak / frozen / error）、请求数、保存数、详情失败数。
2.3.2 ✅ 采集事件流（搜索、详情尝试、保存、blocked、stopped 等）持久化，可按时间倒序查询，作为 dashboard 与问题排查的数据源。
2.3.3 ✅ 各源 24h 预算用量可查询（已用 / 限额）。

### 2.4 后台管理页面

2.4.1 ✅ 新增后台管理区域，**仅管理员账号可见可进**；普通用户访问后台地址被踢回首页，后台 API 对非管理员一律拒绝。
2.4.2 ✅ 后台首页为数据流水线 dashboard，包含：
   - 作业卡片：每个调度作业的状态（运行中 / 待命 / 已暂停 / 冷却中）、下次运行时间、连续 streak 次数
   - 各源 24h 预算用量（已用 / 限额）
   - 最近运行记录列表（结局、请求数、保存数、耗时）
   - 最近采集事件流（时间倒序）
2.4.3 ✅ dashboard 上可直接操作：暂停 / 恢复作业、立即触发一次、修改调度参数（周期、会话预算）。
2.4.4 ✅ dashboard 数据自动刷新（轮询），无需手动刷页面。

### 2.5 管理员账号

2.5.1 ✅ 用户增加「管理员」属性；管理员开通只能通过服务端命令行操作，**不提供任何注册/自助提权入口**。
2.5.2 ✅ 前端能区分当前用户是否管理员（用于后台入口显示与路由守卫）。

### 2.6 合规与安全

2.6.1 ✅ 沿用 PRD-006 2.4 全部红线：语料仅个人参考、保留出处、不二次分发；cookie 与 `corpus/` 不进 git；遇反爬升级即停采该源、不对抗。
2.6.2 ✅ dashboard 不展示语料原文内容，只展示运行状态与统计；语料原文仍只在本机语料库中。

## 3. 后续展望（本期不做）

- process 阶段：语料清洗、结构化抽取（与 PRD-006 二期展望衔接）。
- consume 阶段：语料筛选、评分、待读队列。
- emit 阶段：自动生成户外计划模板（与语料转方案的既有转换链衔接，发布前保留人工终审）。
- dashboard 扩展到加工/消费阶段的监控。
