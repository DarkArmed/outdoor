## 一、背景与目标

- 问题：目前出行由爸爸驱动，孩子是"被带着去"。7 岁正是收集欲、闯关欲最强的年纪。
- 目标：让孩子**主动想出门**（"我还差 2 枚徽章"），并把每次活动变成有任务、有回顾、有积累的"冒险"。
- 三个功能共用一条主线：**打卡**——活动结束后在详情页点「完成本次冒险」，一次打卡同时解锁徽章 + 点亮足迹。

## 五、数据与实现约定

- 新增 localStorage 键：`badges:unlocked`（已解锁徽章）、`tasks:<planId>:<idx>`（任务勾选）、`plans:done`（已打卡计划）。
- 徽章、任务定义为**数据驱动**（计划数据新增 `badge` / `tasks` 字段），新增一周自动接入。
- 里程碑徽章的判定规则写死在数据里（如「首次露营」= 第一个打卡的 C 型计划），不做复杂规则引擎。

## 六、待办清单

无——全部需求已实现并验证（2026-08-11 收口：长按打卡 / 解锁动画 / 任务勾选 / 满星版动画浏览器验证通过；摆位按抽屉模型落地）。

## 七、明确不做的（边界）

- 不做账号/云同步：数据只在本机浏览器，换浏览器从零开始（孩子知道规则即可）
- 不做排行榜/分享/社交功能
- 不用真实 GPS 定位打卡：信任制，爸爸确认即打卡
- 不做惩罚机制（不扣徽章、不过期）：激励只增不减
