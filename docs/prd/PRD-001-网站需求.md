## 一、项目背景

- 亲子户外活动规划项目（爸爸 + 7 岁男孩，北京，自驾，9 月起每周末一次）。
- Markdown 计划文档已齐备（16 个活跃计划 + 8 个备用）；网站是其**图文版呈现**，面向父子两人使用，尤其要吸引孩子。
- 网站原为**本地纯静态站**（双击 `site/index.html` 即可用）；自 v1.1 起按**前后端分离**演进（React 前端 + FastAPI 后端，需 Node 构建 + Python 运行），为未来可部署服务做准备。

## 六、用户配置需求

> 本章定义**需求**：配置里有什么、必须遵守什么规则。
> 字段级契约（类型/消费方）见 [技术文档·数据契约](../tech/数据契约.md)。
> ⚠️ 隐私红线：真实值一律不入库、不进任何已提交文档（docs/README 全局规则 5）。

### 6.1 配置内容

用户配置由以下字段组成（字段名即配置键）：

**家庭位置**——用于自驾起点与路线规划：

| 字段 | 含义 |
|---|---|
| `home.name` | 家的大致位置（街道/地铁站级，不写门牌） |
| `home.city` | 所在城市 |

**出行成员**——用于页面文案、装备与餐饮按人数：

| 字段 | 含义 |
|---|---|
| `family.travelers` | 常规同行人列表 |

**孩子信息**——用于页面文案、强度匹配、餐饮安全：

| 字段 | 含义 |
|---|---|
| `child.name` | 孩子小名 |
| `child.birthYear` | 孩子出生年份（年龄自动计算，不存年龄数字） |
| `child.enduranceKm` | 孩子可接受的徒步里程范围（下限～上限） |
| `child.interests` | 孩子兴趣列表 |
| `child.character` | 性格特点（自由文本） |
| `child.allergies` | 过敏/忌口列表（无则留空） |

**出行偏好**——用于新计划生成约束：

| 字段 | 含义 |
|---|---|
| `prefs.maxDriveHoursOneWay` | 可接受的单程车程上限（小时） |
| `prefs.availableDays` | 可出行日列表 |
| `prefs.activityTypes` | 活动类型偏好列表 |
| `prefs.foodNotes` | 餐饮备注（自由文本，无则留空） |

### 6.2 规则

| # | 规则 | 验收方式 |
|---|---|---|
| 6.2.1 | 代码、计划数据、页面文案**不得写死**用户画像信息；发现写死点视为缺陷 | 改配置后不改代码即可生效 |
| 6.2.2 | 真实值只存于本地配置文件，**永不入库**；仓库内提供占位模板供参考与换机恢复 | `git status` 不出现真实配置文件 |
| 6.2.3 | 修改家庭位置后，全部路线图可按新起点**重新生成**，无需手改任何数据文件 | 重跑流水线后路线图起点正确 |
| 6.2.4 | 孩子年龄按出生年份自动计算，跨年龄增长**无需改任何配置或文档** | 跨年显示自动 +1 岁 |
| 6.2.5 | 新增配置字段 → 先改数据契约文档，再改模板与相关代码 | 契约文档与代码字段一致 |

## 八、明确不做的（边界）

- 不做真实 GPS 导航（导航用高德/两步路 App，网站路线图用于指路参考）
- 本阶段（前后端分离）**不实现**用户登录、多用户、数据库；此为后续服务化阶段演进方向，届时另行开 PRD
- 不做照片级真实图片（统一卡通 SVG 风格）
- 冬季 1–2 月暂不出逐周计划，只有总览文档（12 月已排：滑雪/观鸟/冰雪乐园/滑冰）
