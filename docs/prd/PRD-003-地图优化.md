# PRD-003 · 地图视觉优化

> 编号：PRD-003 ｜ 版本：v1.0 ｜ 日期：2026-08-11 ｜ 状态：**已确认（方案 A）**
> 主题域：活动详情自驾图 + 徒步图 + 足迹大地图的视觉质量。依赖 PRD-001（页面渲染）与 route-pipeline（真实地理数据）。
> 需求项状态：✅ 已实现 ｜ 🔨 待实现 ｜ ⚠️ 部分实现/待验证 ｜ ❌ 已取消。

## 一、背景与目标

- 问题：当前卡通地图「太丑，没眼看」。具体病根（代码级）：
  - 单一浅色底 + 一条装饰波浪 = 横幅感，无地形无层次；
  - 路网（network.js）三档路近白米色（`#D9D2C5/#DFDAD0/#E6E2DA`），对比度极低，像污渍；档位之间几乎无区分；
  - 路线是「18px 白边 + 11px 珊瑚红」的糖果粗线；
  - 路名标签是深色大 pill（`#4A5568` 圆角块），像贴纸，喧宾夺主；
  - 地标/起终点是「白圈 + 高饱和色环 + 大 emoji」，浮在地图上互不呼应；
  - 整体配色饱和度过高且杂乱（`#FF6B6B/#A78BFA/#FFA94D/#FFD93D/#7CDB6E`）。
- 目标：在**不换技术栈、保持零依赖/离线/数据驱动**的前提下，把三张地图从「贴纸拼贴」提升为「精致旅行手账图」。
- 硬约束：**所有文字/数据内容不得丢失**（里程、地名、emoji、活动标注、备用标注、打卡状态）；`node tools/smoke-test.js` 保持全绿。

## 二、三个备选方案

### 方案 A｜程序化矢量精修（零依赖）——【选定，主观判断理由见文末】
在不换技术栈的前提下彻底重构 SVG 视觉层：
- 莫兰迪/纸色系：暖纸底 + 柔和水绿 + 低饱和道路分层 + 淡 graticule 经纬网；
- 道路分级渲染（白描边 + 层次色：高速琥珀 / 干道米色 / 主路白灰），替代近白污渍；
- 文字「光晕」排版（`paint-order:stroke` + 纸色描边），替代重型 pill 色块；
- 统一 pin 标记体系（白底 + 强调色环 + 小 emoji + 软阴影），去浮标感；
- `feDropShadow` 软阴影滤镜、柔和地形叠层、精修指北针/信息牌；
- 足迹大地图：纸色底 + 淡路网 + 金色已打卡 / 灰未去 / 家蓝色锚点 + 底部图例。

- 优点：完全契合「纯静态/零依赖/离线/数据驱动」；自动覆盖全部 17 个计划与未来新计划；冒烟测试可覆盖。
- 缺点：仍是示意矢量图，非真实照片级。

### 方案 B｜OSM 真实瓦片底图（离线预缓存）
route-pipeline 阶段按目的地范围抓 OSM 栅格瓦片存为静态底图，SVG 路线叠加其上。
- 优点：观感最接近真实地图。
- 缺点：瓦片体积大、OSM 需署名；**中国区 GCJ-02 ↔ WGS-84 偏移需纠偏（数百米误差）**；瓦片随上游更新需重抓；偏离「程序生成/零依赖」理念。

### 方案 C｜高德静态地图 API 预渲染
pipeline 阶段调高德静态图 API 把「底图 + 路线 + 标记」渲染成一张静态图片，页面 `<img>` 引用。
- 优点：真实地图观感；高德 GCJ-02 与现有坐标一致、无偏移问题。
- 缺点：构建期依赖外部 API + 配额 + key；图片不可交互（足迹图 hover 提示、打卡变色、同城去重都做不了）；离线仅靠预烘焙图片；偏离零依赖。

## 六、明确不做（边界）

- 不用真实卫星/街景/OSM 瓦片底图（方案 B、C 已评估放弃）；
- 不改数据生成链路（routes.js / network.js 字段与坐标不动）；
- 不做地图交互（拖动/缩放/图层开关），保持静态 SVG；
- 不引入任何新依赖或网络请求。

## 七、选型说明（主观判断）

选 **方案 A**：三张图本质是「给孩子看、信息量适中、随计划自动生成的指示图」，最匹配的形态是**精致的手账/绘本地图**而非真实导航图。方案 A 在不引入网络依赖、不破坏数据驱动的前提下，用一套克制的配色 + 道路分级 + 光晕排版 + 统一标记，能一次性解决"贴纸感、污渍路网、重型标签、杂色"四个病根，并且新计划零成本自动接入；B、C 虽观感更"真"，但破坏零依赖、引入 GCJ/WGS 偏移或外部配额，且交互能力反而变差。
