# 文档中心

> 本目录存放项目的所有**规范类文档**（需求、决策、技术）。计划类文档仍在 `plans/`。
> **规则：新增任何文档，必须先在下方索引登记，并遵守对应分类的规范。**

## 一、目录组织

```
docs/
├── README.md               # 本文件：全局规则 + 总索引
├── prd/                    # 产品需求文档（规范见 prd/README.md）
│   ├── README.md
│   ├── PRD-001-网站需求.md
│   └── PRD-002-成长激励与足迹.md
├── adr/                    # 架构决策记录（ADR-xxx）
│                           # 记录"为什么这么做"：关键岔路口的取舍，追加式不改旧文
└── tech/                   # 技术文档（规范见 tech/README.md）
    ├── README.md
    ├── 数据契约.md
    ├── 网站.md
    ├── 路线流水线.md
    └── 操作手册.md
```

## 二、分类说明

| 分类 | 目录 | 写什么 | 什么时候新增 | 细则 |
|---|---|---|---|---|
| **产品需求文档** | `prd/` | 某主题域的需求（What），是施工依据 | 出现新主题域时 | [prd/README](prd/README.md) |
| **决策记录** | `adr/` | 重要取舍及理由（Why）；追加式，旧文不改 | 有多个合理方案、做出大影响选择时 | 本文件第三节 |
| **技术文档** | `tech/` | 数据契约、模块机制、操作手册（How） | 出现新技术领域时 | [tech/README](tech/README.md) |

> 三者边界一句话：**PRD 管 What，ADR 管 Why，tech 管 How**。实现细节（可调参数、代码技巧）不另起文档，写代码注释。

## 三、全局规则（所有文档共同遵守）

1. **编号**：PRD/ADR 编号三位递增、不回收（删除的编号退役，如 ADR-002）；tech 文档用领域名，不编号。
2. **版本纪律**：版本号与修订记录**统一只在提交时更新**——未提交的改动不动版本号、不写修订记录。
3. **文档头**：PRD/ADR 开头写 `编号 · 版本 · 日期 · 状态`（草稿/已确认/已归档）；tech 文档开头写 `版本 · 日期`，文末带「修订记录」。文档头不写流程规则。
4. **状态标记**（全文统一）：✅ 已实现 ｜ 🔨 待实现 ｜ ⚠️ 部分实现/待验证 ｜ ❌ 已取消。
5. **隐私红线**：个人敏感信息（家庭住址、真名、联系方式等）**一律不写入任何入库文档**，文档中统一以「用户配置」指代，实际值只存在于 gitignore 的本地配置文件。
6. **引用方向**：ADR → PRD/tech 单向引用（ADR 里写"关联需求"）；PRD 不引用 ADR。
